## Batched findings for the original author

**F1 — Missing explicit zero-ID consumer behavior (coverage gap, medium).** Candidate dossier lines 24 and 30 distinguish host-object IDs and table capacity but do not say what the selected consumer does when the ID is zero. Issue #1 explicitly requires partial/missing paths and zero/unknown IDs. The actual consumer has a positive fallback, rather than automatically rejecting the texture: `gx_object_id` returns 0 for null/missing objects; bounded insertion failure leaves a new object absent; `render.cpp` selects `texture_view` by descriptor words when `id == 0`. Enabled diagnostic word mismatch also produces zero and therefore selects that fallback. A same-address object re-registration updates the slot to a new counter value; this differs from an unseen object or zero original resource ID. A readable resource field whose masked low 24 bits are zero is not rejected by `register_holder`.

Evidence: [object producer/table](https://github.com/droogie/bbhost/blob/566184a74f071166299bb656c4af479e5bbe2771/src/engine/gx_resources.cpp#L184-L209), [zero-return lookups](https://github.com/droogie/bbhost/blob/566184a74f071166299bb656c4af479e5bbe2771/src/engine/gx_resources.cpp#L797-L823), [resource mask and registration](https://github.com/droogie/bbhost/blob/566184a74f071166299bb656c4af479e5bbe2771/src/engine/gx_resources.cpp#L252-L299), [optional mismatched-word fallback](https://github.com/droogie/bbhost/blob/566184a74f071166299bb656c4af479e5bbe2771/src/hle/gx_trace.cpp#L974-L997), [actual renderer branch](https://github.com/droogie/bbhost/blob/566184a74f071166299bb656c4af479e5bbe2771/src/host/render.cpp#L8558-L8578).

Required result: make these distinct source outcomes explicit, with a raw zero-ID versus nonzero-ID conditional case, without asserting original ID uniqueness, object immutability, runtime table exhaustion or universal successful fallback. No new runtime test or atomic claim is required.

**F2 — Failed registration reads do not establish absence of later ahead work (coverage gap, medium).** Candidate dossier lines 36–38 accurately state that failed safe reads add no entry and that a creation error counter does not gate registration. The later caller phase remains unstated: `register_holder` returns on any failed field read before replacing a prior record, then `gx_res_after` searches `g_by_holder` without a success result from that call. With a retained old record at the same non-1D key, a readable output pointer, and an eligible old type/initial-data/memory plus captured T#, it can copy that record and call `create_ahead`. Thus “registration read failed” distinguishes no newly installed record from no record/no queued downstream work. The existing new-holder control is valid with no prior key; it must not be generalized to reused keys.

Evidence: [failed read before replacement](https://github.com/droogie/bbhost/blob/566184a74f071166299bb656c4af479e5bbe2771/src/engine/gx_resources.cpp#L252-L299), [error counter branch](https://github.com/droogie/bbhost/blob/566184a74f071166299bb656c4af479e5bbe2771/src/engine/gx_resources.cpp#L613-L625), [unguarded subsequent lookup/copy/dispatch](https://github.com/droogie/bbhost/blob/566184a74f071166299bb656c4af479e5bbe2771/src/engine/gx_resources.cpp#L649-L683), [eligibility predicate](https://github.com/droogie/bbhost/blob/566184a74f071166299bb656c4af479e5bbe2771/src/engine/gx_resources.cpp#L340-L367).

Required result: document this caller-phase distinction with retained-key and absent-key conditional outcomes. Preserve it as a source deduction; the original producer's error/output behavior and natural schedule are unknown. No reachable failure or stale upload is demonstrated.

## Independent source and contract assessment

The public GitHub API pinned tree independently matches all 17 dossier blob identities. Raw GitHub bytes additionally match Git and working-file hashes for `gx_resources.cpp`, `textures.cpp`, `gpu.cpp` and `kernel.cpp`. The detached source checkout is clean at the exact commit. This binds source identity; it does not validate its assertions.

Producer/adapter: actual field widths and offsets, masked resource ID, synthetic 1D key, initial-pointer sequence, object counter and saved-register order were inspected. `GUEST_ABI` and prologue/return adapters establish source hook behavior; game register meanings and the labelled known-1.09 hash correspondence remain reports. Individually refused hooks, disabled registry, field read failure and bounded object table are observation limits. Destructor handling is at entry, creation/Map accounting at intercepted return. Full natural coverage was not inferred from a hook count.

Map/lookup: a known holder with unchanged pointer, failed memory reread, non-write type or unsuccessful Map return still advances the event sequence. Unknown holder does not install a record. Current range lookup copies fields under a temporary lock, carries no retained reference and does not explicitly check `alive`. A released holder can be reindexed by a subsequent different nonzero Map pointer while `alive=false`; Map collision handling differs from registration. Strict flip comparison cannot order equal-flip creations. Normal bounded arithmetic/nonoverlap premises remain necessary. These are source-conditional deductions, not executed races.

Ahead/consumer: `AheadJob` saves T#/range, no original-resource token. The guard checks current range; the later host lock is separate. Existing Surface at the decoded base causes unconditional ahead refusal, including failed surfaces. Absent Surface permits descriptor resolution subject to mapping/format/layout/reserve checks. Render-target alias success can return without making a Surface and therefore does not alone make the ahead wrapper succeed. Ordinary bind can defer incompatible shape/format/mip replacement or refresh compatible content. Word memo verifies words/flags/epoch; ID memo uses ID/flags/epoch and assumes descriptor immutability unless optional word checking is enabled. Refresh includes dirty-watch policy, once-per-recording, hash cadence/budget, GPU/CP flags and prep-readiness guards. `census_upload` attributes already selected uploads; it is not the trigger. Neither every old job overwrites a replacement nor every old job is generation-bound follows.

Preparation: `TexturePrep` holds raw guest source/layout and shared prep ownership. CPU async jobs enter `g_batch_preps`; batch waits complete prep before staging submission. Staging/scratch spans are retained by slot/user bookkeeping and released after normal fence retirement ([allocation](https://github.com/droogie/bbhost/blob/566184a74f071166299bb656c4af479e5bbe2771/src/host/gpu.cpp#L4263-L4355)). Hash-only GPU-route jobs do not enter that CPU batch. `settle_prep` waits for hashes when consumed, but erasing/resetting a Surface does not cancel a pool-held job. `content_hash_of` itself dereferences `base` directly without a mapping recheck ([raw hash reader](https://github.com/droogie/bbhost/blob/566184a74f071166299bb656c4af479e5bbe2771/src/host/textures.cpp#L634-L684)); `run_prep` hashes after CPU untiling and in the hash-only branch. Prep-object/staging ownership therefore does not establish the guest allocation's retention. Imported GPU reads remain a distinct path; full import-reclamation audit is excluded.

Retirement/completion: holder removal, whole-page write-watch release and range queueing diverge. Memory-release scans bases starting inside the interval, so a resource beginning before a partial unmap is not visited; surface retirement uses the same base-start limitation. `protect_range` invokes `maps_cut_locked` before re-adding mapping pieces, so protection also issues release notification; naming a counting protection callback does not prove membership preservation. Unmap cuts records/forgets watches/notifies GX, then host-unmaps outside the map lock. Mapping/watch helpers return observations, no enduring lease.

CP insertion/retirement totals aggregate asynchronous jobs across queues; sync queue-0 bypasses their increments. A retirement entry is due at `after <= retired_total`; current full-span coverage keeps a Surface even when it belongs to replacement B. Conditional cross-queue later jobs can fill a total while an earlier particular job is outstanding: aggregate count is not an identity prefix. Deferred views/images/ranges go to the current slot, whose normal cleanup waits for submission handoff then a successful Vulkan fence. Submitted serial is published after the queue-submit attempt, including error. Fence timeout/loss skips normal cleanup and completion advancement; separate failed-submit/idle and shutdown paths are qualified rather than declared universally safe. No CPU total is relabelled GPU completion.

RC-0004/0005/0006 are supported with these limits. Positives and contradictory raw-field cases were reasoned against function bodies/callers; checker flags, source comments and the Director draft were not treated as proof.

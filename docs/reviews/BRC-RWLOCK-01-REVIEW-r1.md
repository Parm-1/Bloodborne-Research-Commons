The following conclusions come from the selected source and API text, not author checker flags or generated expectations.

1. Producer/ABI/admission: traced all 166 lines of runtime_rwlock.c, including Windows exclusion. This does not validate caller storage or prove guest reachability/original ABI. Public C typedef casts do not prove function-type compatibility.
2. Init/lazy positives and negatives: explicit init never reads old *out; NULL attr uses native defaults and name is ignored. NULL out or readable attr pointing NULL maps EINVAL/raw 0x80020016; other readable non-NULL attr exits 21. Successful explicit replacement allocates separate native storage, leaving old registered ownership accessible through a valid saved alias. Only slot 0 lazily creates; tombstone 1 is rejected. Failure to allocate a Holder after successful lazy creation can leave a registered handle and created increment without ownership (ENOMEM/raw 0x8002000c).
3. Ownership: native success is the source of each read increment or writer=1. Same-owner writer reacquisition and read-to-write forms reject before native use: try EBUSY/raw 0x80020010 versus blocking/timed EDEADLK/raw 0x8002000b. Shared and recursive read positives require native success, matching releases, applicable host policy and nonoverflow. One successful recursive read unlock does not remove other ownership. No fairness, scheduler/progress, general deadlock avoidance or automatic upgrade/downgrade follows.
4. Strong retention positive at applicable public phases: inflight and pending increment before registry unlock and the host call. They stay set during pre-native admission, native waiting/try, deadline validation, and native-success-before-bookkeeping even when this Holder's readers/writer remain zero. Destroy checks inflight OR any Holder before native destroy. Success bookkeeping records ownership before releasing registry_lock; failed bookkeeping can prune the last Holder. These source-faithful phases support L3/D1, including the positive guard when owner fields alone would be misleading. A pending=1 negative cannot distinguish waiting from pre-native or already returned host success.
5. Cleanup versus return: after acquire's final registry unlock there is no more r/h/native dereference, only error(e). A failed acquire can therefore be locally quiescent before its guest error return; after other owners release, destruction can retire native storage in that gap. Successful acquire instead leaves recorded ownership. Unlock runs native release and bookkeeping while registry_lock is held. The mechanism neither joins unadmitted calls nor closes caller-slot/deadline/data/thread lifetimes. No generic callback-lease analogy was imported.
6. Timed phase: timed entry first calls native try. Only EBUSY reads deadline; available try=0 succeeds even for NULL or invalid nanoseconds, while self-conflict prechecks bypass time entirely. Busy NULL/out-of-range nanoseconds gives EINVAL without native timed call; other try errors also bypass time validation. Valid busy time casts signed int64 fields to native timespec and reaches native timed read/write. No wrapper clock sample, relative addition, remainder or seconds-range validation exists. Named POSIX timed API descriptions use absolute CLOCK_REALTIME and permit immediate acquisition despite expired time. Installed representation, host implementation and elapsed timing are not qualified.
7. Errors: captured local e, rather than errno, feeds the explicit raw32 SCE mapping: EPERM1, EDEADLK11, ENOMEM12, EBUSY16, EINVAL22, EAGAIN35, ETIMEDOUT60 under 0x80020000. Zero stays zero; unmapped errors exit21 after any reached cleanup. No POSIX rwlock errno adapter is present. Invalid native ownership/destruction is not an expected-error positive. Ignored registry mutex returns require successful host synchronization as a premise.
8. Retirement/lifecycle: valid nonowner wrapper unlock rejects EPERM before native unlock, preserving the real owner's record. Host unlock0 removes one matching ownership and prunes only empty/no-pending Holders. Host destroy0 with no inflight/Holders removes/frees r and writes tombstone only to the passed slot; native failure retains it. Copied aliases have no generation field; no actual allocation reuse/ABA is evidenced. Cancellation, nonlocal exit, thread exit/invalid pthread IDs, retention overflow, allocation failures and synchronization bypass remain bounds, not observed failures. Global created/reads/writes/unlocks are cumulative completed-bookkeeping counters, not per-object occupancy, native-gap closure or thread completion.

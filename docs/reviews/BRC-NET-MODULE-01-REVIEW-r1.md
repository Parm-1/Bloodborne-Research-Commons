## F1 — spawn return is not ordered before entry completion

Severity: medium; demonstrated source-contract defect, not missing runtime evidence. Affected candidate: knowledge/net-module.md:62, paragraph beginning “The module create wrapper”. It asserts “return0 is earlier than entry completion”. That creates an unsupported temporal predicate at a lifetime-sensitive observation phase.

Decisive producer source at the pinned bbport commit:

- src/runtime_thread.c:233–248 creates the GuestThread record, stores entry/argument and publishes the handle before pthread_create.
- Lines249–255 call pthread_create, then destroy attrs, update created/print and return0. There is no barrier ordering the worker's entry completion after this return.
- host_start at220–227 calls attach (TCB/TLS setup), executes the entry, performs ordinary cleanup, marks finished1 and returns. These worker operations can all occur while the creator has not yet returned0. Conversely, attachment/entry may not yet have begun when the creator returns.
- runtime_thread_spawn at325–332 simply performs the attr/create adapter and returns its normalized result; it supplies no extra ordering. The glue callback at280–284 supplies no such ordering either.

A source-faithful falsifier is a valid ordinary-return worker whose attach/entry/cleanup/tail finish while the creator is delayed after successful pthread_create and before its own return0. This is a permitted hypothetical schedule, not an observed run or generated fixture. The opposite schedule leaves attachment/entry pending at return0. [Linux man-pages pthread_create](https://man7.org/linux/man-pages/man3/pthread_create.3.html) describes scheduling indeterminacy after creation; it is API-description support, not installed implementation qualification. The already reused Commons knowledge/thread-lifecycle.md:56 explicitly says entry/attach may not have started or may already have ended.

Affected repair condition: remove the asserted ordering and distinguish creator-side record/handle publication from worker-side attach/TCB/TLS and entry/tail phases. State only what successful creation establishes; completion requires the matching join endpoint under the existing contract. Check interaction with N19 and RC-0065, whose current matching-join distinction is otherwise sound. Preserve the frozen r1 author/candidate/review evidence; use a linked successor version.

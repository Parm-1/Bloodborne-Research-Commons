## Actionable finding

**F1 — narrow the consumer's nonzero/uniqueness validation statement.** Location: `knowledge/import-resolution.md:31`, sentence “The probe validates index, unique nonzero binding, kind 1/2 and containment in a declared module.” The consumer does not validate that every serialized binding address is nonzero, and uniqueness is checked through an address-valued sentinel.

Evidence: [probe.c lines 443–458](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/probe.c#L443-L458) permits a module base and initializer at zero when its size and other metadata are valid. The binding predicate tests index, containment, kind and `bindings[index]`, with no `!address` rejection; it then assigns `bindings[index]=address`. A zero-address entry therefore leaves the duplicate sentinel clear. The same index with a subsequent zero or nonzero entry is not rejected by that sentinel. [Lines 487–497](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/probe.c#L487-L497) skip a zero address, and [lines 533–538](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/probe.c#L533-L538) do not select it for fallback.

Contradictory raw-field case, reasoned from source and not executed: BBPROBE5 with image size 4096, a mapped segment starting at zero, module base/init zero and size 4096, valid zero TLS metadata, import_count 2 and nb 2, and two `(index=0,address=0,kind=1)` triples passes this binding predicate. Valid surrounding metadata and content are still required. Replacing the second address with a valid in-module nonzero offset also passes the duplicate predicate after the first zero entry. This contradicts an unconditional nonzero-and-unique validation guarantee.

The ordinary producer positive remains supported: [link_modules.py lines 95–127 and 193–206](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/scripts/link_modules.py#L95-L206) places linked modules after the prepared main image and emits bindings from indexed identities. For ordinary valid producer output, module/binding offsets are nonzero and the consumer's sentinel catches repeated indices after a nonzero entry. The finding concerns the documentation's raw serialized-consumer guarantee, not an observed malformed input or a requested upstream fix.

Correction condition: explicitly distinguish normally produced nonzero offsets from the consumer's sentinel-based duplicate check; state that zero addresses are not explicitly rejected and are treated as absent afterward. Recheck that paragraph and any changed dependent summary or worked case in a linked r2 or later, preserving r1 and its evidence. No runtime fixture or source modification is needed for this documentation repair.

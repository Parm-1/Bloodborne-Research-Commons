## Producer, ABI, phase and control assessment

The following checks independently follow actual producer branches and field assignments. Candidate examples and document-check flags were not treated as producer evidence. The twelve rows are conditional reasoning controls, not twelve executed tests, fixtures or independent trials.

1. **Setup and typed count (row 1).** Source validates initialized state, length 256 through 2048 in multiples of 256, 48000 frequency, low-byte format 0 through 7, type range and slot availability before constructing the port. For length256/param1, channels2/sample_bytes2 give samples512, bytes1024 and integer period5333333ns. Each input sample is synchronously read with memcpy before the return. Length257/frequency44100 are rejected; param0x101 still selects format1. Handle positivity alone does not distinguish a stream from fallback. Interface fields and sysv_abi describe this host source, not original SDK or Windows qualification.
2. **Timer route (row 2).** BB_AUDIO=none, failed initialization, or failed stream open can leave streamNULL. The conversion loop and return512 remain applicable on the stable readable stereo input, with no Put call. This is a source-faithful contrary to return-as-acceptance or return-as-played claims.
3. **API acceptance/copy (row 3).** The stream receives local converted bytes, not the guest source pointer. Put's boolean is discarded. Same-call Put=true under a compatible API contract supports a copy of that converted span; Put=false has the identical source return and cannot support acceptance. Resume=false is also discarded. These supplied API premises do not establish any actual runtime result or played endpoint.
4. **Conversion/remap/gain (row 4).** Source-channel gain is applied before writing the target index. Eight-channel nonstandard remap is 0,1,2,3,6,7,4,5; param6 leaves indices unchanged. Distinct c4/c6 values with c4 half gain distinguish the two layouts despite equal samples2048/bytes4096. Source construction also supports the omitted maximum F32 bound: length2048/param7 gives samples16384/bytes65536/period42666666ns, within the local conversion/silence capacities and int byte parameter. Formats3/4/5/7 use the four-byte float branch; format6 uses S16. No clipping, acoustic fidelity or target layout validation follows.
5. **Pacing and NULL phase (row 5).** A new zero deadline takes the startup branch without sleep; later non-null paced calls with a saved deadline within the stated restart threshold call absolute monotonic sleep at that deadline. This need not wait a full period, and persistent sleep errors can loop. NULL data skips conversion, stats, pacing, queue logic and buffer count, but still updates last_output_us and returns0. The positive startup arithmetic is conditional on the declared clock premise, not a measured duration.
6. **Measured versus substituted queue (row 6).** For bytes1024/measured queued0, the source attempts1024 silence bytes, then assigns local queued2048 without another query. Even true silence Put does not establish a measured2048 occupancy. False Put and query failure -1 take the same local substitution path. The statistic query and pacing-control query are separate pre-submission samples; -1 may enter stat_min_queued but cannot be interpreted as occupancy.
7. **Window correction (row 7).** On a 32nd control sample, source window_min above4096 selects positive period/32, while a possible measured minimum1024 through2047 selects negative correction; below1024 gets substituted2048 instead. The full preceding window, not just its final query, determines that minimum. adjust_ns persists between updates and is added through uint64 arithmetic. Samples512 remain unchanged. This supports control-state reasoning, not measured drift correction or playback.
8. **Multiport and partial failure (row 8).** Only index0 requests pacing. A later NULL entry can make the final wrapper result0 after earlier non-null processing; a later invalid handle returns its error without rollback. NULL index0 makes all later entries unpaced. Different frame lengths are not independently waited. These are body facts, conditional on valid native OutputParam storage/count and stable slots; no serialized layout or selected import binding for Outputs is proven.
9. **State and last-time (row 9).** Open zeroes last_output_us. State zeroes all32 bytes then assigns type-derived output/channel/volume; default eight-channel setup reports channel2 and volume0, not configured stereo, mute or gain. Reroute/flags/reserved zeroes are construction values. NULL output may later change time with no buffer. State and time readers release table_lock and do not take the slot lock; consistency under concurrent mutation is unqualified.
10. **Volume partial effect (row 10).** With valid readable native volume storage, selected c0=16384 is written before selected c1=32769 produces invalid-volume. That error does not restore c0. A later conversion must use the actual post-error gain premise, as the candidate says.
11. **Close and incarnation (row 11).** Close destroys the stream, closes the dump and clears used under its locks. An old handle then returns not-opened until reopening; a reused low-byte slot has no generation protection. Output and volume have a lookup-to-slot-lock gap, and state/time read without slot locking. Reopen zeroes and reinitializes the mutex without an explicit prior destroy. Stable serial open-slot and valid pthread-operation premises are necessary; this is source-level lack of a retained incarnation lease, not an executed race. Successful close is not a drain-to-played receipt.
12. **Reachability (row 12).** Exact `QOQtbeDqsT4#G#H` maps to sceAudioOutOutput. runtime_lookup first requires the exact scoped table entry and then matches exports; top-level selection additionally needs capability bit0, non-data import and no earlier match. The selected probe consumer installs resolved address plus addend. Exact searches find no sceAudioOutOutputs or sceAudioOutGetLastOutputTime names in the pinned import table. Export presence and literal function-name input do not establish binding through that table. The candidate correctly limits this absence claim to the selected path; it does not prove global unsupported functionality, other-route absence or actual game invocation.

## Independently inspected official API evidence

All six official primary pages were independently opened and read during this review, separately from the candidate and memory:

- [SDL_PutAudioStreamData](https://wiki.libsdl.org/SDL3/SDL_PutAudioStreamData): int input-byte length, boolean result, matching input format, copying unconverted bytes for later conversion. This supports the conditional copy boundary, not physical-device completion.
- [SDL_GetAudioStreamQueued](https://wiki.libsdl.org/SDL3/SDL_GetAudioStreamQueued): input bytes or -1 failure, distinct from output-ready data; format changes and int clamping affect interpretation. It supplies no attributed played endpoint.
- [SDL_OpenAudioDeviceStream](https://wiki.libsdl.org/SDL3/SDL_OpenAudioDeviceStream): playback spec is the application input; NULL callback requires application feeding; created device begins paused; destruction closes it.
- [SDL_ResumeAudioStreamDevice](https://wiki.libsdl.org/SDL3/SDL_ResumeAudioStreamDevice): boolean success/failure, unpauses the associated device. Source ignoring the result prevents positive stream identity from proving successful resume.
- [SDL_DestroyAudioStream](https://wiki.libsdl.org/SDL3/SDL_DestroyAudioStream): releases queued data, unbinds and closes a device created by the convenience API. No drain-to-playback promise is documented.
- [SDL_AudioSpec](https://wiki.libsdl.org/SDL3/SDL_AudioSpec): format, channel count and frame rate in the source initializer's order.

## Batched findings and affected recheck conditions

**F1 — returned error can differ from the failed host syscall errno.** Dossier line57 says “return-host errno”; line68 describes helpers as retaining “-host errno”; row11 at line92 concludes internal `-EINTR` from the first host `-1/EINTR`. The source does not snapshot that errno. After `read_retrying` returns negative, [runtime_file.c:416–436](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_file.c#L416-L436) calls `audio_trace()` and may call `printf()` before evaluating `return -errno`. `audio_trace` can also initialize its environment lookup at line222. The existing EFAULT-touch caveat identifies only an earlier part of this unsnapshotted path.

A source/API countermodel supplies an otherwise eligible descriptor/span, first host result `-1` with `errno=EINTR`, enabled audio trace, and a diagnostic `printf` that returns normally with an output failure setting `errno=EIO`. There is no retry or positive post-note, but the helper returns `-EIO`, and its adapters map that current error, rather than the original `EINTR`. This is permitted source/API reasoning, not an executed failure or installed-libc observation. The primary [printf description](https://man7.org/linux/man-pages/man3/printf.3.html) says output failure returns negative and sets errno; the primary [errno description](https://man7.org/linux/man-pages/man3/errno.3.html) also allows successful functions to change errno. Normal function return therefore does not supply errno preservation.

Required repair: distinguish raw final syscall errno from the later helper-return errno, qualify exact-error positives with preservation through retry touches, trace lookup/output and applicable intervening handlers, and make the phase table, row11 and ABI/claim/report wording consistent. Preserve the supported no-retry/pre-touch/no-post conclusions and direct lookup `-EBADF` example, which returns before this diagnostic path. Source code changes, new runtime tests and broader logging research are unnecessary. Recheck the changed error contract, exact errno-dependent rows, helper/POSIX/Orbis adaptation and cumulative prose references against the same source.

**F2 — row13 does not bind clipping to a source-producible span and phase.** Dossier line94 begins with positive final `n=7`, then states that nine eligible disjoint VMAs dispatch only the first eight “per call.” It supplies no requested count, span or pre-versus-post distinction for that contrary. The generic endpoint cap is correct: [runtime_memory.c:740–754](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_memory.c#L740-L754) collects at most eight eligible intersections. However, the file pre-note uses the requested span, while the post-note uses seven bytes. A half-open seven-byte span at integer addresses cannot intersect nine nonempty disjoint VMA intervals with integer endpoints: each positive intersection occupies at least one of those seven bytes. This bound does not depend on 16KiB alignment. In particular, [runtime_memory.c:554–560](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_memory.c#L554-L560) computes end before rounding start down, so mapping page-size checks alone are not a universal VMA-edge invariant. The current row does not prove which call has the supplied ninth intersection; this is missing evidence, not a demonstrated defect in the endpoint cap or proof that no larger request can clip.

Required repair: supply a concrete producer-compatible requested span and eligible VMA arrangement, identifying clipping at the pre-request phase and separately the seven-byte post phase, or explicitly make the large-span contrary a separate endpoint scenario. Preserve invalidate-null suppression even when a note hook exists. Recheck changed row premises against the actual interval/notification producer and file pre/post call phases; reuse unchanged downstream memory receipts. No fixture execution or new memory campaign is needed.

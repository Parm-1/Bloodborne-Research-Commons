# AudioOut submission, input consumption and completion

**Proposed Batch 02 source topic, BRC-AUDIO-SUBMISSION-01 / [Issue #16](https://github.com/Parm-1/Bloodborne-Research-Commons/issues/16) item 2.** SOURCE_INSPECTED, checked 2026-10-13; [Independent review r1](../docs/reviews/BRC-AUDIO-SUBMISSION-01-REVIEW-r1.md) found no actionable defect in the source/documentation scope at frozen `ff13fcf439568f868f0bf2de5c11a8a99cb5e83d`. Root accepts this contract for one PR delivery only; human editorial acceptance/consolidation/merge remain pending. Audio remains a peer-reviewed proposed topic, not an additional accepted topic. [Author integration r2](../docs/reviews/BRC-AUDIO-SUBMISSION-01-AUTHOR-r2.md) records this status-only delivery. This answers one maintainer question: **what does a returned AudioOut call establish about its input, SDL acceptance and queue accounting, pacing, and actual playback completion?** [RC-0022](../claims/RC-0022-audio-submission.md) owns submission/input consumption; [RC-0023](../claims/RC-0023-audio-completion.md) owns completion limits; [frontier](../frontiers/audio-submission.md) owns the remaining consumer question. No runtime, serialized fixture, native fixture, device or game result is supplied.

At the pinned implementation, a normally returned valid non-null call has finished the synchronous reads and conversion of its input under the stable-port premises below. Its positive return is a computed interleaved sample count. A stream branch attempts to submit converted bytes to SDL; it discards the submission result. A timer branch returns the same count without SDL submission. Neither return proves that SDL accepted those bytes or that a device played them. The SDL contract is a separately inspected official API description, not a binding to an installed library.

## Separate SDL API contract

Official SDL3 descriptions read 2026-10-13, mutable documentation with no exact documentation revision bound here. They mark these APIs available since SDL 3.2.0. That is API availability, **not the version used by bbport**. The inspected build consumes ambient pkg-config `sdl3`; the inspected Nix expression imports ambient `<nixpkgs>`. No installed/linked SDL version, artifact digest or runtime behavior was acquired.

| Official primary reference | Contract used here |
|---|---|
| [SDL_PutAudioStreamData](https://wiki.libsdl.org/SDL3/SDL_PutAudioStreamData) | Takes an int byte length and returns bool success/failure. It copies input for later conversion. Required format/rate/channels belong to the stream's input specification. A successful call ends that call's use of the supplied bytes; it is not a playback-completion event. |
| [SDL_GetAudioStreamQueued](https://wiki.libsdl.org/SDL3/SDL_GetAudioStreamQueued) | Returns int input-byte count, or -1 on failure. This is not output-ready frames; conversion occurs as data is consumed. Input-format changes and int clamping complicate interpretation. An input queue sample does not identify the device's played endpoint. |
| [SDL_OpenAudioDeviceStream](https://wiki.libsdl.org/SDL3/SDL_OpenAudioDeviceStream) | Creates/binds a stream and device, or returns NULL; playback spec describes the application's input. NULL callback means application feeds the stream. Device starts paused; destroying this stream also closes its device. |
| [SDL_ResumeAudioStreamDevice](https://wiki.libsdl.org/SDL3/SDL_ResumeAudioStreamDevice) | Unpauses associated device; returns bool success/failure. bbport ignores that bool, so non-null stream alone does not establish successful resume. |
| [SDL_DestroyAudioStream](https://wiki.libsdl.org/SDL3/SDL_DestroyAudioStream) | Releases stream data including queued audio, unbinds and closes the device opened by the convenience function. Destruction is not a documented drain-to-playback wait. |
| [SDL_AudioSpec](https://wiki.libsdl.org/SDL3/SDL_AudioSpec) | Format, channel count and sample-frame rate. bbport supplies its chosen S16/F32, channels and 48000 in that order. |

## Setup, ABI and applicable routes

The source uses `sysv_abi`, fixed-width `int32_t` return/handle/user/type/index, `uint32_t` length/frequency/param and a native `const void *` data pointer. This establishes the declared host implementation interface; no original console SDK ABI, real caller layout or Windows qualification is established. The selected import consumer is a relocation binder, not an observed audio-producing game call.

`audio_init` sets global initialized and returns 0 first time, ERR_ALREADY_INIT subsequently. `audio_open` ignores user/index; before port creation it rejects not-initialized, length 0/over 2048/not multiple of 256, frequency other than 48000, low-byte format >7, unsupported type, or full selected type range ([setup](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_audio.c#L58-L129)). Other param bits do not choose the source format. Types select slots 0–7 main, 8 BGM, 9–12 voice, 13–16 personal, 17–20 pad, 21–22 type126 and 23–24 type127. There are 25 slots.

Format 0/1/2 uses S16 and 1/2/8 channels; 3/4/5 uses F32 and 1/2/8; 6 is S16 eight-channel standard layout; 7 is F32 eight-channel standard layout. `frames` is the validated length converted to int; `sample_bytes` is 2 or 4, `std_layout` is format>=6. New slot fields are zeroed, per-channel int32 volume defaults to 32768. The input extent is frames × channels × sample_bytes; a non-null pointer is not checked for length, validity or stability. Caller must supply that readable extent with no conflicting writer through the conversion reads.

Backend initialization is cached: `BB_AUDIO=none` or failed SDL initialization selects no stream. Successful SDL initialization attempts the default playback stream; NULL also keeps a timer sink. A non-null stream triggers an unchecked Resume call. Open still returns `(type<<16)|id|0x20000000`. Positive open result does not distinguish audible setup from timer fallback.

Handle lookup checks `(handle & 0x3f000000)==0x20000000`, low-byte id<25 and `used`. It does not validate encoded type or a generation. Output/state/time/volume release table_lock after lookup; output/volume then acquire the slot lock. Close acquires table_lock and slot lock, destroys stream/closes dump and clears used. No retained port-incarnation lease exists between lookup and slot-lock acquisition ([lookup/close](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_audio.c#L78-L152)). Reopen zeroes the slot and reinitializes its mutex without an explicit prior destroy. Thus the worked positives require serial calls on a stable open slot, no concurrent close/reopen/configuration writer, and valid pthread operations; these premises are not guaranteed by the handle bits. A close/reopen interleaving prevents attributing a pointer/old handle to the old incarnation. This is a source-condition limit, not an executed race result.

Exports list Output, Outputs and GetLastOutputTime. `runtime_audio_resolve` uses RUNTIME_LOOKUP, which first requires an exact scoped NID in `import_names` and then matches its symbol. Output has mapping `QOQtbeDqsT4#G#H`; Outputs and GetLastOutputTime have no names in this pinned table, so their function bodies do **not** imply successful binding through this resolver ([exports](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_audio.c#L264-L271), [lookup](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime.c#L263-L278)). Direct symbol-name input also fails the selected table path. The selected top-level runtime resolver first requires capabilities bit0 set and is_data false. Positive exact NID selection still needs relocation/input eligibility and actual invocation before becoming an execution fact.

## Submission phases and field meanings

The entire selected operation is [output_port / wrappers](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_audio.c#L145-L223).

| Phase | Source-produced facts | What is not established |
|---|---|---|
| Lookup, slot lock | Invalid/not-opened returns negative before processing. Under stable-slot premise, computes size_t samples=frames×channels and bytes=samples×sample_bytes; uint64 period=frames×1000000000/48000 in integer ns. | Pointer validity, original SDK contract, retained incarnation across concurrent close. |
| Non-null conversion | Reads every input sample with memcpy into local stack `converted` (capacity 2048×8×4 bytes), applies volume[c]/32768. Eight-channel non-standard layout maps source channels 4,5,6,7 to target 6,7,4,5; standard layout leaves indices. Mono/stereo unchanged. Float multiplication or S16 cast; no independent clipping/fidelity proof. Optional dump writes converted bytes, with ignored fwrite result. | An original-game mixer's ownership, unchanged input version, dump write success, SDL/device use. |
| Optional stats, before pacing | uint64 times/gap; unsigned stat_buffers increments for non-null calls. SDL queued int sampled before this submission; queued==0 increments stat_starved, -1 can become min. Five-second report is source clock/count aggregation. | Count is not accepted/played buffers; a zero sample is not an attributed audible underrun; failure -1 is not valid queued bytes. |
| Pacing | Only `pace!=0` and non-null data. Zero deadline or now>deadline+8×period restarts at now without waiting; otherwise absolute monotonic sleep loops until clock_nanosleep returns 0. Adds one period. | First call waits a period, every call waits a full period, sleep cannot fail/hang, scheduler timing, actual hardware cadence or playback completion. |
| Stream control and Put | Measured queued int; low=2×bytes. If queued<bytes, tries up to bytes silence, ignores result, then **assigns queued=low**, even if silence failed or added only one buffer. Window min/count and int64 adjust are driven by this substituted value. Every 32 buffers correction is ±period/32 or 0; adds adjustment via uint64 arithmetic, then attempts converted Put and ignores bool. | `queued=low` is a computed control value, not a second SDL measurement. Neither silence nor converted Put success is returned; queue target/clock-drift comments are project explanations, not measured device facts. |
| End | `buffers_out` size_t increments for every non-null valid processed call, including timer sink or failed Put. `last_output_us` uint64=monotonic now_ns/1000 after submission attempt; unlock; return int32(samples). Null data skips conversion, stats, pacing, Put and count, still writes last_output_us and returns 0. | Neither count nor timestamp is a played sample position. Cross-port counters lack a common lock; concurrent attribution is unqualified. Null return is no drain or completion wait. |

`next_deadline_ns` is scheduling state, not an SDL cursor. `window_min`/`window_count` are int control fields, not an accepted-byte ledger; `adjust_ns` is signed int64 but added through uint64 cast. Source comments about FMOD ring sizes, clicking, PipeWire 21 ms quanta and PS4 equivalence remain PROJECT_REPORTED; no such target observation is imported here.

`audio_outputs` has a native struct containing int32 handle then pointer (native alignment/padding, not a serialized ABI fixture), uint32 count. It rejects NULL params and count 0 or >25. Processes entries in order, with pace only at index0; returns first negative error immediately, preserving earlier submissions, or the **last entry's** result. It does not sum samples or roll back. If index0 data is NULL, it performs no wait and later ports are unpaced. Different frame lengths do not acquire per-port waits. These are function-body facts; its resolver applicability remains absent as above.

## State, last-time, volume and close

[State/time/volume](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_audio.c#L224-L262): PortState declares uint16 output, uint8 channel/reserved, int16 volume, uint16 reroute, uint64 flag/reserved64[2]; static assertion total size32. Source zeroes the whole result then writes type-based fields: types2/3 output0x40/channel1; type4 output0x04/channel1/volume127; default output1/channel=min(channels,2). This does not report configured eight channels or live gain for every type. Reroute/flags/reserved remain zero by construction, not device acknowledgments. State/time readers do not take the slot lock, so concurrent mutation/read consistency is unqualified.

Last-time writes the stored microseconds (zero after open, changed even by NULL output) into a uint64 pointer. It is not device playback position. Volume accepts selected channel flags and values in [0,32768]; it writes in channel order and may return invalid-volume after earlier selected channels changed. NULL volume returns invalid-pointer; invalid handle returns its error first. It is not a transactional all-channel configuration.

Close returns0 after destroying stream, closing dump, clearing stream/used, or a lookup error. Official SDL Destroy releases queued audio, so normal close does not demonstrate that queued samples were played. Input reuse for this source call and disposal of queued stream data are different boundaries; there is no playback-completion event in these selected exports.

## Reuse decision, outcome branches and stop rule

**KNOWLEDGE_REFERENCE** for one maintainer deciding whether call return closes input reads or playback. **DEFER** runtime/code reuse until consumer establishes exact call route, compatible SDL artifact/API, serial slot ownership and input span/version. This proposal neither changes nor corroborates the peer proposed memory topic. Seven earlier accepted technical topics retain their status; both usability results remain NOT MET, Issue #9 OPEN.

For a future authorized observation, first attribute one non-null invocation to an exact stable port incarnation and source pin, establish input format/extent/writer ordering and SDL artifact. If normal return occurs, source-call input reads are closed under those premises. If separately attributable Put=true is recorded for that same converted span under the compatible API, acceptance/copy is supported. If Put=false or timer route occurs, return cannot support acceptance. Neither branch supports actual playback completion; that requires a separately attributable device/playback endpoint whose semantics have been established. Queue0, synthetic window low, counter or last-time alone fails that decision. A concurrent close/reopen or unreadable/conflicting input invalidates the positive setup rather than producing a valid negative sound test.

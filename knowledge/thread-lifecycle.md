## Producer → attach → entry

[link_modules.py:210–223](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/scripts/link_modules.py#L210-L223) takes the first type7 program header and serializes four little-endian uint64 fields `(vaddr, filesz, memsz, align)` into BBPROBE5; absent header yields four zeros. It rejects filesz>memsz, memsz>1MiB and template file end beyond image size. [link_libc.py:160–188](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/scripts/link_libc.py#L160-L188) supplies the corresponding BBPROBE4 path. The actual [rewrite](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/scripts/link_modules.py#L77-L89) scans file-backed bytes of type1 executable segments for exactly `64488b042500000000`, replacing only its first byte with65. BBPROBE5 scans main and selected modules; BBPROBE4 scans main only. This is a byte-pattern scan, not an instruction-boundary decoder, all-FS instruction conversion or rewrite-fidelity proof. A patch count alone is insufficient. Alternate instruction encodings, data matches and unscanned code remain outside this guarantee.

[probe.c:403–449](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/probe.c#L403-L449) reads those four fields for versions4/5; version3 leaves main metadata zero. For linked formats it rejects filesz>memsz, memsz>1MiB, vaddr>size, filesz>size-vaddr, non-power-of-two nonzero align or align>4096. align0 passes and setter substitutes16. This check bounds file bytes, not the entire static memsz as a mapped/readable source span; it does not require main template coverage by a readable segment. Module TLS has separate mapped metadata checks. Metadata validity alone is not successful attach.

`native_libc = linked && !strict_imports && (capabilities&1)`. Only this branch calls setters, then main attach, then procparam and module initializers in table order, before main entry ([probe.c:555–589](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/probe.c#L555-L589)). A module initializer's nonzero result fails; main entry has a distinct ABI/signature, manually mapped8MiB stack and unexpected-return failure. Guest pthread entry is not module initialization or the main entry. Relocation consumes runtime_resolve before native fallback ([probe.c:528–542](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/probe.c#L528-L542)); accepted [import dossier](import-resolution.md) owns unchanged import-selection rules. Exact thread resolver tables and readable NIDs do not prove an actual import/call occurred.

[attach:56–109](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_thread.c#L56-L109) borrows `data` in process-global template fields without copy, validation or synchronization. Setup must precede attachment and stay stable; the template must remain readable through each filesz copy. offset is `(memsz+align-1)&~(align-1)`. It allocates64-aligned rounded `(offset+256)` bytes, zeroes only `offset+256`, copies filesz at block start, then puts TCB at block+offset. Slots0/1/2 hold TCB self, pointer to one shared zero-initialized static `dtv[3]`, and GuestThread pointer. No DTV module population or generation is shown. Bytes after filesz through the zeroed allocation are zero except those three TCB writes. This actual layout is not proof of every guest compiler's TLS ABI.

Under admitted loader sizes and align0/valid powers≤64, normal allocation provides the corresponding base alignment; offset provides rounding. For align128..4096, fixed64 base allocation does not guarantee requested alignment of block/TCB. Runtime setter itself admits values outside loader checks; unchecked integer/size conversions and invalid metadata are excluded from defined positives. Allocation failure exits1. `ARCH_SET_GS` error exits21; only after successful call is host-thread-local `current` set. No prior GS save/restore is present. GS success and guest access correctness remain execution facts absent here. [runtime.c:52–68](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime.c#L52-L68) has a separate lazy module2..7 TLS allocator/get_addr with bounds/STOP behavior; static DTV does not establish that module TLS, unload, dynamic growth or its cleanup correctness. Full dynamic TLS is DEFER/UNKNOWN.

`runtime_thread_current` returns existing current or allocates, sets pthread_self and host_owned1, attaches, and publishes. Main/host attach then rename the record. This path creates no `host_start`, exit_jump setup, finished flag or guest key-cleanup endpoint. ## Handle → completion → retention

The [record and registry](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_thread.c#L26-L115) use `GuestThread*` as guest handle, distinct from separate TCB and pthread_t. Registry search compares addresses under mutex; no slot integer or generation exists. thread_equal compares pointers without membership validation. No GuestThread removal/free or TLS free is present in this selected file, including after successful join/detach. A retained record is not a live host-thread certificate or permission to reuse its expired pthread_t. A completed host-owned wrapper can leave a discoverable record with finished0. Arbitrary invalid pointers, names/output storage and attr lifetimes are not safely validated generally.

Seven accepted technical topics retain their scope; peer memory/audio proposals remain independently reviewed, unmerged and unaccepted. Both usability results remain NOT MET and Issue #9 OPEN.

One consumer is an input maintainer deciding whether one ReadState/Read record or capability return can identify a physical controller incarnation and fresh acquisition. **Use the result as a host composite sample under explicit setup, not an identity or freshness witness.** The source fills connected=1 with or without a gamepad, timestamps the host sampling operation, merges keyboard/mouse/controller and optional synthetic input, and supplies fixed motion fields. Vibration success can mean no pad or an ignored SDL failure. This finding is a conditional source contract, not controller, original-hardware, native ABI or game behavior.

## Raw fields, output ownership and lookup

[Definitions and static assertions](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_pad.c#L40-L76) declare PadData's uint32 buttons; uint8 sticks/triggers; float orientation[4], acceleration[3], angular_velocity[3]; uint8 touch_count; uint32 touch_held_time; two PadTouch records (uint16 x/y, uint8 id); uint8 connected; uint64 timestamp; extension[16]; uint8 connected_count/unique_length and unique[12], plus padding/reserves. Assertions name sizes PadData120/PadTouch8/ControllerInfo28 and offsets touches60/timestamp80. They are source constraints, not a compilation receipt or original ABI proof; float representation, all other offsets, actual guest call and compiler artifact are unqualified. `ABI` is [declared sysv_abi](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime.h#L13-L16). Correct native interface and writable full output extent are supplied premises; null checking is not a buffer-size check.

ReadState validates handle1/opened and non-null output, then under its pad mutex fills the caller's record and increments size_t `reads`, returning int32 0. Read accepts count1..64, calls ReadState for exactly the first record, ignores its return and returns int32 1. It does not fill count records or expose a sample sequence. `reads` is a process diagnostic printed later, not a record sequence or poll/event count. No caller output pointer is retained. Return closes this call's source writes only under a normally returning, valid serial stable-open setup; it does not retain an input-device incarnation. Concurrent close/open is outside that setup: guard reads and close write are not protected by the sampling lock. [Operations/diagnostic](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_pad.c#L699-L766).

[Exports](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_pad.c#L757-L765) exist for Init/Open/Close/ReadState/Read/Info/Vibration/reset/deadband/tilt/motion flag. Selected [NID mappings](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/import_names.inc#L259-L266) plus [Init mapping](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/import_names.inc#L663) include all except Read and SetMotionSensorState. [runtime_lookup](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime.c#L263-L278) accepts exact scoped table NIDs, converts to a symbol, then matches exports; an export entry or literal `scePadRead` name alone does not establish selection. [runtime_resolve](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime.c#L204-L254) first requires capabilities bit1 and rejects these as data; [relocation consumer](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/probe.c#L528-L542) prefers a nonzero resolved address, otherwise uses linked fallback or traps. This is conditional address selection, not a guest-call or ABI correctness observation. Claims about Read and the motion helper below describe function bodies even where the selected lookup lacks their names.

## Identity, phase and lifecycle

Init sets a single initialized flag. Open requires initialized, user1, type0 or2, index0; param is ignored. One global opened flag grants the fixed PAD_HANDLE1, with already-open error0x80920004; no per-user/type/index/device generation is returned. Close validates that same handle and only clears opened; it does not close SDL gamepad, clear counts, reset calibration, touch IDs, wheel/replay state or `reads`. Reopen reuses handle1. Invalid argument/handle/not-initialized errors are int32 casts of0x80920001/03/05. [Init/open/close](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_pad.c#L699-L716).

[Selector](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_pad.c#L209-L251) lazily initializes SDL_GAMEPAD once (failure makes sdl_ready=-1), closes a cached SDL gamepad when SDL_GamepadConnected returns false, and enumerates when none exists or a requested preferred device has not been selected and more than1,000,000 microseconds passed since scan. BB_GAMEPAD is read once: case-insensitive GUID string equality or case-insensitive name substring; fallback is ids[0] only when no cached pad. Preferred switching can replace an existing fallback. Every attempted replacement resets calibration; every successful SDL_OpenGamepad increments uint8 connected_count, including replacement/reconnect, with modulo256 wrap. It is neither simultaneous-device count nor exposed SDL instance ID. Official GetGamepads returns current connected instance IDs (NULL failure); GetGamepadID gives an opened instance ID (0 failure). bbport uses these for selection but exports no such ID or GUID in PadData/Info: unique_length/unique remain zero from memset. GUID/name preference is a selector, not a guaranteed physical-device identity.

sample_host [sets connected=1, fallback count and timestamp before querying current_gamepad](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_pad.c#L499-L517). Count is the old uint8 counter when nonzero, otherwise1. Thus replacement increments can lag one record; wrap0 is masked to1. pad_info instead queries the selector before writing that fallback count. Neither operation reports disconnected=0. Keyboard-only or SDL init/open failure can produce connected1. Ordinary pad close does not establish SDL/device retirement.

The [window constructor](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/gpu/shim/window.cpp#L57-L100) initializes VIDEO|GAMEPAD. [bbgpu_init](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/gpu/shim/bbgpu.cpp#L265-L303) creates a separate window thread, publishes readiness, and loops PollEvents with SDL_Delay(2); this declared delay is not measured poll cadence. [PollEvents](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/gpu/shim/window.cpp#L156-L242) calls SDL_PollEvent and accumulates captured mouse relative motion/wheel. [TakeMouse](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/gpu/shim/window.cpp#L116-L147) transfers and clears accumulators under a mouse mutex; capture resets old accumulation, F1/focus loss releases, and menu/prompt/settings release capture. [Input adapters](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/gpu/shim/bbgpu.cpp#L397-L419) query menu/prompt capture and mouse state; [capture predicate](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/gpu/shim/bbport_overlay.cpp#L854-L861) is menu_open||prompt_active. No whole UI audit is needed for this predicate.

Official PollEvent may implicitly pump events and is restricted to the video-initializing/main thread; GetKeyboardState exposes SDL's internal array updated by event pumping, and a press/release between updates can be absent. The chosen GetGamepads/ID/axis/connected/touch/rumble descriptions allow calls from any thread; eligibility of actual initialization/event pumping remains unknown. The pad mutex serializes these bbport sampling bodies, not SDL pumping or an atomic snapshot across all devices. ReadState does not itself call PollEvent, PumpEvents or UpdateJoysticks. Its uint64 timestamp is successful CLOCK_MONOTONIC host time in microseconds taken before device query, not an SDL event/report timestamp or elapsed time since acquisition; successive outputs can reuse unchanged SDL state despite advancing time. No freshness threshold, hardware report sequence or synchronized poll-to-read relationship is returned.

## Composite inputs and capabilities

[sample_host](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_pad.c#L499-L553) clears all120 bytes, sets sticks128, orientation[3]=1, connected/count/time, then queries the selected pad and lazily loads bindings. With a stable true overlay capture at both checks, it consumes mouse accumulation, resets mouse look and returns neutral without host controls, record/replay/injection or touch IDs. Overlay state changes between its two checks are not promised atomic. Otherwise controller button/trigger getters supply bound values (max across bindings); values>30 set button bits, while uint8 trigger values retain their scaled analog value. Sticks pass through calibration/dead-zone conversion, then keyboard buttons OR in, held keyboard directions replace stick axes and mouse look may replace right stick. A missing SDL_VIDEO gives no keyboard pointer; keyboard still contributes next to a selected controller. Default Options comes from controller START or keyboard Return; contributions are indistinguishable in output bits. [Bindings/configuration](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_pad.c#L273-L405), [keyboard/axis/mouse precedence](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_pad.c#L408-L497).

BB_CONFIG is read once when bindings load: key./pad. replaces that input's respective bindings, empty unbinds; up to four names, unknown names logged, pad stick-direction bindings rejected. mouse_look, invert_y and sensitivity change mouse transformation. BB_PAD_CENTER/CENTER_CAL/DEADZONE/DEADZONE_OUTER and BB_MOUSE_DEADZONE change interpretation. Calibration resets on selected SDL replacement, not PadOpen. Source quiet-window thresholds are eight qualifying samples, delta<=512, all-zero postponement until3,000,000 microseconds, and biased center only when all four magnitudes>=8192; these are caller-sample counts, not eight distinct hardware reports. Clone/game-fidelity comments are not proven. [Calibration/axis conversion](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_pad.c#L84-L199).

[sample postprocessing](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_pad.c#L683-L697) records the host sample before synthetic changes; BB_PAD_FILE is first-bound, checked no more often than20,000 microseconds, and parsed only after mtime changes. stat/open failure keeps prior injected state; empty successfully read file releases injected contributions. Tokens OR buttons, touch clicks can replace touch state, trigger-button injections force255, and lx/ly/rx/ry override sticks after replay. BB_PAD_REPLAY loads once when armed, uses local elapsed milliseconds and latest due row to replace buttons/sticks/triggers; after last-row+500ms it stops overriding. Thus record rows omit later injection/replay, and neither a recorded row nor replayed current timestamp establishes device acquisition. [File/replay/record producers](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_pad.c#L555-L667).

Controller touch uses touchpad0, at most two currently down successful finger queries, float coordinates mapped to x0..1919/y0..942; pressure is ignored. Default Back/touchpad button without a reported touch creates left synthetic touch(480,471); right creates(1440,471). Keyboard Tab/Backspace and file tokens also create touches. [Touch source](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_pad.c#L536-L550), [touch_ids](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_pad.c#L668-L682) assigns1..127 cyclic IDs by occupied output slot across calls, and uint32 host-microsecond held duration since first occupied touch; slots compact fingers and are not SDL finger identities or a device generation. State is static across PadClose/reconnect; stable overlay skips its update. Original controller touch protocol/fidelity is UNKNOWN.

[ControllerInfo](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_pad.c#L732-L744) is cleared then fixed pixel_density44.86, resolution1920×943, dead zones2, connection_type0, connected1, device_class0; selected-pad query affects only counter. These are compatibility values, not measured dimensions, dead zone configuration or an advertised sensor/rumble capability result. Motion fields remain the cleared zero acceleration/angular velocity and identity orientation; no inspected sample sensor getter/enable branch exists. [Reset/deadband/tilt/motion helpers](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_pad.c#L754-L764) only validate handle; flag ignored, no state change. Success establishes the guard at this source phase, not an enabled sensor or changed motion filter. [Vibration](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_pad.c#L745-L753) validates handle/non-null two-byte-readable param premise, queries current pad, calls SDL_RumbleGamepad if any with byte×257 amplitudes and1000ms duration, ignores bool and returns0 even without pad. Official Rumble documents true/false success/failure and requires event processing or UpdateJoysticks for rumble-state updates. No rumble capability query, completion or physical vibration proof is returned.

# Shader and pipeline cache applicability

**Proposed topic — BRC-CACHE-APPLICABILITY-01, 2026-10-13. SOURCE_INSPECTED; independent review pending.** Target: public bbport `3c57da4198ad62039f63f33bfd205b9916518acf`, its shadPS4-derived Vulkan renderer. Consumer: a renderer maintainer deciding whether a cached module and pipeline remain selectable after a buffer descriptor or render configuration changes. [RC-0016](../claims/RC-0016-module-compatibility.md) and [RC-0017](../claims/RC-0017-cache-domains.md) summarize the two findings; this dossier owns the contract and examples. [Author r1](../docs/reviews/BRC-CACHE-APPLICABILITY-01-AUTHOR-r1.md), [frontier](../frontiers/cache-applicability.md).

**Reuse decision: ALREADY_PRESENT for this implementation's selection mechanism; KNOWLEDGE_REFERENCE for another renderer.** Keep the existing program → directional specialization → pipeline-key path when assessing one live buffer change. A program-hash hit alone does not select a module. A module hit alone does not select a graphics pipeline. This is a source-derived eligibility decision, not validation of cached machine code, a device or a game. No dependency on an unmerged Commons shader dossier, no upstream source imported, and no execution performed.

## From actual producer to lookup and draw

On the regular graphics path `RefreshGraphicsKey` zeroes key storage, captures depth/topology/color information, then refreshes stages; it can repeat stage selection for motion vectors and finally fills attachment masks, blending and samples. Stage refresh starts `Bindings{}` and processes fragment first, followed by the enabled hardware-to-software stage mapping. Each active stage calls `GetParams` from that stage's program registers, then `GetProgram`; absent/disabled stages get zero stage values. Without vertex-input dynamic state, fetch-attribute formats also enter the pipeline key. [C 720–790](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/gpu/shadps4/video_core/renderer_vulkan/vk_pipeline_cache.cpp#L720-L790), [C 793–898](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/gpu/shadps4/video_core/renderer_vulkan/vk_pipeline_cache.cpp#L793-L898), [C 901–1023](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/gpu/shadps4/video_core/renderer_vulkan/vk_pipeline_cache.cpp#L901-L1023).

`BuildRuntimeInfo` initializes stage-specific storage, then derives register properties and stage inputs. Selected vertex inputs include output map, clip controls, motion flag, step rates and indirect SGPR offsets; fragment inputs include interpolation, exports, samples, color-buffer data and blend-related flags. Tessellation initialization also reads constants. `RuntimeInfo::operator==` compares hardware/software stage, properties, and the selected union comparators; it is not whole-object byte equality. For example, compute equality omits `shared_memory_size`, and geometry equality uses truth tests for both invocation counts rather than count equality. These are exact predicate observations, not stale-cache findings; their compiled influence and valid changing producer premises require separate investigation. [C 109–287](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/gpu/shadps4/video_core/renderer_vulkan/vk_pipeline_cache.cpp#L109-L287), [U 71–178](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/gpu/shadps4/shader_recompiler/runtime_info.h#L71-L178), [U 233–343](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/gpu/shadps4/shader_recompiler/runtime_info.h#L233-L343).

The regular `GetProgram` branches are distinct:

1. **Absent program value:** constructs a new `Program`, translates/emits a module, then builds its stored specialization from the analyzed `Info` and the saved precompile binding start; stores ordinal zero and metadata, and publishes the program under its value. Resource layout is discovered during translation, before that stored specialization is made. [C 1113–1131](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/gpu/shadps4/video_core/renderer_vulkan/vk_pipeline_cache.cpp#L1113-L1131), [T 63–114](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/gpu/shadps4/shader_recompiler/recompiler.cpp#L63-L114), [X 198–216](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/gpu/shadps4/shader_recompiler/ir/passes/resource_patching_pass.cpp#L198-L216), [X 940–965](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/gpu/shadps4/shader_recompiler/ir/passes/resource_patching_pass.cpp#L940-L965).
2. **Present program, compatible module:** updates `pgm_base` and user data, refreshes flattened user data, builds the current specialization, checks the last-used stored specialization and then the list. On hit, advances bindings with `Info::AddBindings`, reuses the module and returns the matched ordinal's combined value. [C 1134–1173](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/gpu/shadps4/video_core/renderer_vulkan/vk_pipeline_cache.cpp#L1134-L1173), [I 236–249](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/gpu/shadps4/shader_recompiler/info.h#L236-L249).
3. **Present program, no compatible module:** ordinal starts at current list size; compilation uses a new `Info` and current code/runtime/bindings, stores another module and the current specialization. This is a permutation miss, not necessarily a program miss. [C 1146–1173](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/gpu/shadps4/video_core/renderer_vulkan/vk_pipeline_cache.cpp#L1146-L1173).

`CompileModule` translates then emits SPIR-V using the per-cache profile. Patch lookup uses hardware stage, program value and ordinal in its filename; if a patch exists and the setting is enabled, Vulkan module creation uses the patch. Registration still receives the generated SPIR-V. Patch enable/content is consulted at compilation, not in the specialization hit predicate; no live-patch invalidation guarantee follows. [C 1034–1065](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/gpu/shadps4/video_core/renderer_vulkan/vk_pipeline_cache.cpp#L1034-L1065), [C 1204–1246](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/gpu/shadps4/video_core/renderer_vulkan/vk_pipeline_cache.cpp#L1204-L1246).

## Directional specialization contract

Let **stored** be the left operand and **current** the right operand, matching the explicit last-used check. The list search compares stored projections to the current value. Under a same-program resource layout, the operator does the following, in order; it is compatibility, not ordinary symmetric descriptor equality. [S 197–248](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/gpu/shadps4/shader_recompiler/specialization.h#L197-L248), [C 1151–1155](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/gpu/shadps4/video_core/renderer_vulkan/vk_pipeline_cache.cpp#L1151-L1155).

- Reject an invalid left `info` pointer. Compare vertex-attribute specializations, runtime info, fetch data and FMasks before any early return. Pointer identity and equality of validity bitsets are not compared.
- If both buffer/image/FMask validity bitsets are empty, accept immediately; binding start and samplers are bypassed by this branch. This observation does not certify all sampler-only behavior.
- Otherwise require identical binding start (`unified`, `buffer`, `user_data`). Then compare each stored buffer/image entry only if the **current** validity bit is set; samplers are compared without that bit guard. The loops use stored list lengths and assume matching program layout, not arbitrary malformed/different-length records. [B 10–16](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/gpu/shadps4/shader_recompiler/backend/bindings.h#L10-L16).

A buffer is truthy when `num_records != 0`; `Valid()` instead tests type zero. `GetSharp` fetches raw words from tracked immediate/flattened locations, applies its post-operation and returns a null descriptor on fetch/type failure. The producer appends each specialization, sets its bit only for a truthy descriptor, and fills:

| Input | When it contributes to buffer compatibility |
|---|---|
| Stride, formatted flag, paged flag, swizzle enable | Always in `BufferSpecialization::operator==` when the current entry is checked |
| Data/number format, destination select, number conversion | Only when the stored `is_formatted` is true; equal formatted flags are already required |
| Index stride, element size | Only when stored swizzle is enabled; equal swizzle flags are already required |
| Base address and record count | Not stored directly; can indirectly change truthiness or `paged` (`enabled && nonzero base && size >= 64 MiB`) |

[D 15–103](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/gpu/shadps4/video_core/amdgpu/resource.h#L15-L103), [R 24–115](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/gpu/shadps4/shader_recompiler/resource.h#L24-L115), [S 24–44](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/gpu/shadps4/shader_recompiler/specialization.h#L24-L44), [S 119–139](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/gpu/shadps4/shader_recompiler/specialization.h#L119-L139), [S 175–195](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/gpu/shadps4/shader_recompiler/specialization.h#L175-L195). The formatted flag comes from analyzed resource instructions, with merged usages OR-ing it; it cannot be freely toggled while holding identical analyzed program usage fixed. Raw descriptors can vary through loaded flattened words. [X 98–113](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/gpu/shadps4/shader_recompiler/ir/passes/resource_patching_pass.cpp#L98-L113), [X 183–216](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/gpu/shadps4/shader_recompiler/ir/passes/resource_patching_pass.cpp#L183-L216), [I 193–198](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/gpu/shadps4/shader_recompiler/info.h#L193-L198), [I 242–249](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/gpu/shadps4/shader_recompiler/info.h#L242-L249).

Stride has a demonstrated compilation consumer: `PatchBufferArgs` reads the sharp and supplies its stride to `CalculateBufferAddress`, which emits immediate stride arithmetic. Swizzle-enabled addressing also embeds index-stride and element-size constants. For the selected unformatted `LoadBufferU32` premise, the address shift is the default 2, independent of descriptor format. [X 49–94](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/gpu/shadps4/shader_recompiler/ir/passes/resource_patching_pass.cpp#L49-L94), [X 546–635](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/gpu/shadps4/shader_recompiler/ir/passes/resource_patching_pass.cpp#L546-L635). This establishes a concrete reason to distinguish stride from conditionally ignored raw fields. It does not establish that every omitted descriptor field is harmless: `add_tid_enable`, for example, is read by address lowering but is absent from `BufferSpecialization`. Whether that can change in a real consumer's same-program use is a missing target fact, not a bug proven here.

Full descriptor bytes, image allocation identity and every sampler field are not keys. These neighboring fields identify scope, not a second image-cache investigation.

## Source-faithful hypothetical controls

The following are **supplied hypothetical premises**, not captured shaders or generated tool expectations. A hypothetical successfully compiled ordinary vertex program contains a tracked, flattened-user-data guest buffer used only by unformatted raw `LoadBufferU32` with index addressing, zero offsets, no thread-ID addressing and swizzle initially off. Changed descriptor words are loaded from flattened user data, with no immediate or program-base post-operation fixing them. Its stored layout is the same as the current layout; other resource, runtime, fetch and binding inputs are unchanged, both descriptors are type-zero/truthy, base nonzero, size below 64 MiB, and no motion/tessellation/prepared path is selected. Both stride values fit 14 bits. Recompilation here means the source branch, assuming successful translation/module creation; no executable shader is supplied.

| Case and phase | Raw change and derived fields | Supported source outcome; contrary assertion rejected |
|---|---|---|
| P1: module selection | Same program code/metadata value, same loaded descriptor fields and same start | Stored specialization matches; regular hit reuses module/ordinal and advances bindings. This positive is known at source-contract scope; actual hardware execution remains unobserved. |
| N1: module selection | Current stride 16 → 32, `num_records=64`, all other inputs fixed | Size changes 1024 → 2048, still truthy/nonpaged. Stride comparison rejects this stored module. If it is the only module, a new permutation is compiled. For index 3, zero offset, shift 2, emitted element-address arithmetic differs: `(3*16)>>2=12`, `(3*32)>>2=24`. Same binary hash does not justify the old module. |
| P2: module selection | Change only raw format/number/destination-select fields; analyzed usage still unformatted, swizzle off, stride 16 | Constructor leaves these specialization fields at defaults and the equality branch ignores them. Match remains supported; default raw-U32 address shift stays 2. This says nothing about formatted instructions or resource contents. |
| P3/N2: module selection | With swizzle off, raw `index_stride` 0 → 1 changes a descriptor field but not selected specialization. In a separate same-program premise with swizzle on, make the same change | Off: compatible. On: index-stride comparison rejects. Independent lowering math gives index-stride constants `8<<0=8`, `8<<1=16`; code consumes them only in the swizzle branch. A blanket wrong-key assertion for the off case is false. |

A stage-value match cannot substitute for the rendering key. |
| P7/N6: warmup gate | At a separate cache construction, supply correctly sized profile record, matching magic/versions and equal profile; separately supply missing profile or unequal `paged_buffers` | First: proceeds to individual record loading, not unconditional pipeline acceptance. ## Profile, persistence, replacement and lifetime limits

The `Profile` belongs to one `PipelineCache`: constructor derives device limits/features, driver-related lowering choices, environment override, sparse page shift, current memory mode and copy-shader value. Compilation uses it; live specialization receives it (notably for paged classification) but the full profile is not a per-module comparator field. The inspected class has no profile-changing method; its const `GetProfile` exposes a const reference. Comparing across changed instances/device/configurations therefore requires the construction/warmup context, not an invented assumption that a missing live key proves staleness. Device-profile equality compares declared fields; it is not an explicit driver-version or UUID equality. [C 290–361](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/gpu/shadps4/video_core/renderer_vulkan/vk_pipeline_cache.cpp#L290-L361), [H 160–189](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/gpu/shadps4/video_core/renderer_vulkan/vk_pipeline_cache.h#L160-L189), [P 10–64](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/gpu/shadps4/shader_recompiler/profile.h#L10-L64).

Warmup, if enabled, opens the database and checks exact serialized size, magic `0x42425043`, versions binary 9 / metadata 7 / pipeline key 5, and field equality of cached/current profile. Missing/incompatible records request clearing and saving the new profile. Individual loads require matching metadata/binary versions, reject motion-vector vertex metadata, require SPIR-V magic plus at least five words, recreate modules, and preserve permutation ordinals; a compatible module at a conflicting ordinal skips that preload. Exceptions trigger destruction/clearing of loaded programs/pipelines and a fresh store request. These are source gates, not a validation of arbitrary SPIR-V, cross-ABI serialization, driver portability or game-image identity. Graphics keys/support and much metadata are raw serialized layouts; this dossier supplies no serialization receipt.

## Admission, service and timeout phases

[wait_count:57–104](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_sema.c#L57-L104) locks before lookup. Missing ID returns `ERR(3)` (`0x80020003`), before need validation. need≤0 or need>maximum returns `ERR(22)` (`0x80020016`). Sufficient count immediately subtracts the whole need and increments acquired, regardless of a linked queue, block flag or timeout value. Otherwise poll returns `ERR(16)` (`0x80020010`). Otherwise wait with nonnull timeout0 returns `ERR(60)` (`0x8002003c`) and increments timed_out. None of these paths writes timeout. There is no partial token reservation.

Only the remaining blocking path creates a stack Waiter with need and zero-initialized result/done/next, initializes a per-waiter condition using CLOCK_MONOTONIC, appends it at the tail and increments active. attr0/1/2 is stored at creation but no service branch reads it. Tail insertion is list order, not strict FIFO token admission, original priority emulation, host equal priority or starvation freedom. [Signal:105–123](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_sema.c#L105-L123) rejects count≤0 or count>maximum-current before service. Otherwise it adds count and increments signaled once, scans from the head, **skips an unfittable request**, and grants each later fitting request using the remaining count. Grant subtracts all need, unlinks that waiter, sets done1 and signals its event; result stays0. It neither waits for the waiter to reacquire the mutex nor sets a return-order policy.

Timed blocking computes uint64 `deadline = now_ns() + (uint64)*timeout*1000`, then seconds/nanoseconds for an absolute timedwait. The public timeout unit is therefore microseconds; the uint32 input multiplication is widened first. This deadline begins after enrollment/setup, not at function entry or time spent acquiring the global mutex. All loop iterations reuse the same deadline. Null timeout means indefinite condition wait. Conversion to time_t and uint64 deadline arithmetic require representable, nonwrapping values for the numeric positives; installed time_t and extreme-clock behavior are UNKNOWN. now_ns clock failure exits1; host_check on condition init/clock/signal/destroy and non-ETIMEDOUT wait errors exits21. Mutex lock/unlock return codes are ignored, so successful synchronization is an explicit premise, not a checked result.

Timedwait returning ETIMEDOUT only records timeout if done is still0 after mutex reacquisition: it unlinks this same waiter, writes result ERR(60), done1 and increments timed_out. A prior grant/cancel/delete that set done wins even if the host wait reports ETIMEDOUT. Ordinary spurious wakeups recheck done. After done, result is copied; acquired increments only for result0. **Only this blocked path writes a supplied timeout:** error result writes0; success writes floor((deadline-now)/1000), clamped0 when now≥deadline. Thus remainder0 can accompany success, and unchanged timeout on an early error/success is not a remaining-budget computation. No wall-clock epoch or exact elapsed-duration/performance claim follows.

## Cancel, deletion and lifetime

[Cancel/delete:124–157](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_sema.c#L124-L157) visit only linked waiters. Cancel rejects missing ID or count>maximum before changing output. Otherwise wake_all unlinks each current waiter, sets result `ERR(85)` (`0x80020055`), done1 and signals; a supplied int32 output receives the number unlinked. It resets count to initial for **any negative** count, else to the supplied0..maximum, then returns0. It does not service new count into the canceled queue or overwrite already granted waiters. Its output is a cancellation selection count, not a count of returned calls, all active waiters or terminated threads. Guest sem_cancel is not POSIX thread cancellation.

Delete removes Sema from registry, sets deleted1, increments deleted, selects linked waiters with `ERR(13)` (`0x8002000d`) and returns0 after unlocking. Further ID operations return missing; diagnostic lookup returns0. If active0, delete frees Sema immediately. Otherwise it leaves that unregistered object for active blocked paths. Active includes both linked waiters and removed-but-not-yet-cleaned-up waiters. On normal resumption each blocked path, while holding the global mutex, reads its result/writes remainder, destroys its own condition, decrements active and frees deleted Sema if it was last. **That free is before global unlock and this wait function's return.** The Waiter is a local automatic object whose lifetime ends when its block is left; queue removal does not end it. The source never joins host threads here.

For defined normal paths, mutex exclusion prevents a delete from freeing Sema while another semaphore operation is using it under lock. Active retains Sema across the condition wait's mutex release. Once a waiter is unlinked, subsequent semaphore operations cannot signal its stack condition through that list. This is a conditional lifetime argument, not blanket cancellation/fault safety. There is no pthread cleanup handler here; host thread cancellation/nonlocal exit while waiting, invalid/aliased caller storage, concurrent mutation of timeout/output/environment, failing ignored mutex operations, unsigned-active or signed wake-count overflow, unrepresentable clocks, and unrelated data races are excluded from positives. A data-racy C execution is never a defined positive. Other runtime_wait_note users must be absent/ordered for these schedules; its unsynchronized lazy enabled field and diagnostic metadata do not certify whole-runtime concurrency safety. Transitive caller jobs/memory retention and original scheduler/hardware fidelity remain unqualified.

[Diagnostics:158–179](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_sema.c#L158-L179) acquire the same mutex: runtime_sema_waiters counts **only linked nodes of a presently registered ID**, returning0 both for absent IDs and empty lists. The report's created/deleted count successful operations; signaled counts successful signal calls, not token quantity; acquired counts immediate successes and blocked successes after resumption, not all grants already made; timed_out counts zero-budget rejection and blocked timeout selection, not cancellation/delete or every host ETIMEDOUT. The wait-note runs only after a blocked path exits the done loop, before condition destruction and function return. Its interval includes mutex reacquisition and scheduling effects; its sites/count/time cannot establish original call identity, performance, completion of other work or hardware equivalence.

## Decision and limits

Use the matching function's normally returned raw32 result for acquisition/cancellation/deletion outcome under these premises. For call retirement, obtain a separate attributable observation after that wait returns; thread termination needs its own matching join/termination endpoint, and transitive work needs its own ownership contract. Do not treat registry absence, queue0, signal0, cancel0 or delete0 as a join. A particular grant is not retroactively canceled by a later operation that cannot find its unlinked Waiter.

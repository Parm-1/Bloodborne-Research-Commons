## Decision and premises

Treat `Mapped` as the end of a conditional source path through header/record predicates, one declared-size image read, relocation writes and successful protection calls, followed by an **any executable segment contains entry** metadata predicate. It is not an image identity check, a final effective page-permission measurement, successful import invocation, original ABI validation or executed entry. Preserve the small loader mechanism; require a separate matched phase observation before relying on any stronger property.

The selected route is **supplied Linux x86-64, `--cpu-only`, no patches, BBPROBE2 and no linked modules**. Strict mode may be on or off and must be specified. The conditional calculations assume an eight-byte `uintptr_t`, the declared/native little-endian representation, valid compiler/library ABI, stable intended input stream and owned backing, no interfering mutations, and successful dependencies at the phase being considered. For rounding calculations assume positive power-of-two host page size P, valid page-aligned returned backing and representable arithmetic. The program assigns `sysconf(_SC_PAGESIZE)` to `size_t` without validating that result. These are hypotheses, not observations of this host. No compiler oracle or program was run.

Producer conclusions additionally require admitted, successfully parsed input, the prior `game_check.problem(game,SHA256(image))` gate accepting, `inspect_libc` completing, all relevant `struct` values fitting, writes/close succeeding, and reaching the end of framing. None of those input/gating facts is supplied. Hypothetical parsed-load values below show framing implications only, never an actual emitted or feasible original game image. No ELF/SELF, prepared image, code or fixture bytes were obtained, generated or executed.

## Producer framing versus raw admission

[prepare148–215][prepare] selects load types 1 and `0x61000010` in program-header order, without sorting or disjointness checks. Image size is max(vaddr+memsz), limited to 512 MiB, and entry must have one byte in a selected memory span; entry need not have executable flags here. A zero-filled bytearray of that size receives each filesz slice in load order; filesz must not exceed memsz. Later copied file slices overwrite earlier bytes on overlap. A later segment's unfilled memory tail does not re-zero bytes copied earlier. Holes/tails are initially zero, with absolute-symbol relocation writes also possible before serialization. The script's source gate checks this image before its subsequent relocation processing. It is not an authenticated identity field in BBPROBE2.

[Framing236–249][prepare] writes exactly `BBPROBE2`, six little-endian unsigned 64-bit values `(size,entry,ns,nr,ni,capabilities)`, then ns unsigned triples `(vaddr,memsz,flags)`, ni 128-byte names, nr relocation records and the constructed image. Header length is 56; segment/name/relocation widths are 24/128/32. Conditional successful framing length is `56+24*ns+128*ni+32*nr+size`, with no implicit host-struct padding. Relocation format is `<QQqq`: target/kind unsigned64, value/addend **signed64**. Original table addend came from `<QQq`. The reader uses little-endian `read64` for every scalar, including the two signed producer fields, and stores them as uint64; a negative signed value becomes its unsigned bit pattern, not a signed C field. Python [struct documentation](https://docs.python.org/3/library/struct.html) specifies these widths, endian/alignment and out-of-range packing failures (mutable Python3.15 documentation read2026-10-17, not installed Python qualification).

Names are first-seen import-symbol-index order across the two relocation tables, not sorted or necessarily unique strings; source strings are ASCII and NUL-terminated upstream, then length <128 and zero padding at write time. Producer capability is 0/1 from `inspect_libc`'s `_init_env` code-equals-RET test result; it is neither entry validation nor an independently accepted libc contract. Defined absolute-symbol relocations write `<Q` into the image immediately and emit no record; other defined symbols emit kind0/value=symbol+addend/addend0; original kind8 emits kind0/value=original signed addend/addend0. Undefined symbols emit kind1 function or kind2 data, indexed by first symbol occurrence; kind1 requires addend0 and kind2 requires 0≤addend<4096. Kind0's value must fit signed64 when serialized, while its already-applied absolute variant must fit unsigned64. Fitting the serialization field does not prove the pointer destination is mapped.

Producer framing does **not** enforce the consumer's ns≤64, nr≤1,000,000, ni≤100,000, P alignment or flags≤7. Its lower parser allows up to 255 program headers, not 64 selected loads. There is no explicit disjointness, address-order, unique relocation-target or executable-entry invariant. Later source/input/gating/packing requirements can still prevent any particular hypothetical output. Boot output opens in `wb` and writes header/segments **before** checking each name length, and may fail later on packing/I/O; no transactional emission or rollback is promised. `eboot.elf` and other auxiliary output after boot framing are outside this study and were not generated.

[probe399–481][probe] accepts five magic dialects but this study selects only BBPROBE2: no linked header/bindings/TLS metadata is read. After capabilities has no bits except bit0, it calls `runtime_start(strict?0:capabilities)` **before** limit checks: 0<size≤512 MiB, entry<size, 1≤ns≤64, nr≤1,000,000, ni≤100,000. Each scalar needs eight bytes or exits1 with truncated-file error. Segments require address≤size, length≤size−address, address divisible by P, flags≤7; zero length at size is allowed. The subtraction form avoids a wrapping end test. There is no requirement that segments cover the image, are disjoint/ordered, readable or executable. The name read requires ni complete 128-byte elements and one NUL anywhere in each; nonzero bytes after NUL and duplicate/empty names can pass. No ASCII/scoped-name predicate is added by admission.

Each relocation must have eight bytes within **one** segment via `mapped`, kind≤2, a valid import index if kind≠0, addend0 for kinds0/1 and addend<P (kind2). Target need not be aligned or writable/executable in segment metadata; relocation happens while backing is RW. Kind0 value has no mapped/range predicate. Segment-union coverage split across two records does not satisfy `mapped`. Repeated/overlapping targets are not rejected; later writes win on their shared bytes. These are raw metadata predicates, not producer provenance or a safe-input oracle.

## Read, backing, rewriting and permission phases

[probe498–554][probe] calls allocate(round_page(size)), then requests `fread(image,1,size)` and one `fgetc`. A short image read or a returned extra byte exits1. This reads the **entire** declared image, including holes, not only segment file ranges. It contains no hash, signature, content comparison, machine-code validation or per-segment file-size identity check. `fread` shortness merges EOF and error; `fgetc==EOF` merges end-of-file and error; there is no `ferror`/`feof` disambiguation and fclose's result is unchecked. Thus no extra returned byte is established; a clean, exact-length immutable file additionally needs error-free stable-stream premises. [fread](https://man7.org/linux/man-pages/man3/fread.3.html) and [fgetc](https://man7.org/linux/man-pages/man3/fgetc.3.html) descriptions (Linux man-pages6.19 read2026-10-17) support this distinction, not an installed libc observation.

The probe rounds with `R(n)=(n+P−1)&~(P−1)`. Linux allocation first asks [runtime_low_map662–677][memory], which rounds again to **16384**, takes its host rwlock and attempts anonymous private `MAP_FIXED_NOREPLACE` mappings in its low range, advancing low_next even on failed attempts. If it returns NULL, ordinary anonymous `mmap` fallback requests R(size). The low helper checks only MAP_FAILED, not equality to requested address; the [mmap description](https://man7.org/linux/man-pages/man2/mmap.2.html) warns older kernels may ignore NOREPLACE and return another address. Do not promote the source's low-address intent into an actual host address guarantee. Anonymous backing's initial zeroing is a separately described API property. Allocation/locking/kernel behavior, actual P, returned address and extent are absent here. No filesystem sandbox is created by this mapping mechanism.

After reading and closing, CPU-only bypasses bbgpu_init and its image patches; no patch file is applied. However CPU-only does not skip prior CPU checks, option/configuration calls, kernel registration, signal handlers/watchdog, capability startup or trap allocation. Effective bit0 startup can read `/dev/urandom` and initialize the canary. Registration source can start its kernel service thread. No claim of side-effect-free validation or rollback follows. Build text still links the GPU library; CPU-only does not prove dependency-free operation.

The loader allocates function-trap and data-trap areas, sets data-trap requested protections to none, fills function trampolines, then walks relocation records in order. Kind0 stores integer `B+value`; kind1 defaults to function trap `T+32*index`; kind2 defaults to data trap `D+P*index+addend`. A nonzero runtime_resolve result replaces the latter with `resolved+addend`. Strict mode or effective capability0 makes host resolution return0. BBPROBE2 has no linked fallback. Data addend admission is P-based, unlike the producer's fixed4096 bound, and neither validates external object size. Eight native bytes of `uintptr_t` are copied, requiring the stated ABI/representation premises. No import is invoked by this relocation loop. Fallback trap binding still reaches the report: unresolved does not mean eager rejection. Relocation slots and earlier producer absolute writes separate bytes at this phase from both original file bytes and raw post-read bytes.

Next function traps receive requested RX, image `[B,B+R(size))` receives none, then segment i gets requested flags over `[B+a_i,B+a_i+R(s_i))` in file order. Linux flags bits4/2/1 map to requested R/W/X; flags0 requests none. Each nonzero protect result exits1. Within the probe-rounded image, the **last nonempty covering segment's requested flags** determine the final source request for a page; uncovered pages retain none. It is assignment, not OR/union. A segment's partial last page includes bytes beyond its logical span, possibly beyond declared size. Extra low-helper allocation beyond R(size) receives none of these image protection calls and can retain the initial RW request. Do not equate declared image, logical segments, rounded image, or actual backing extent.

The executable_entry variable separately ORs `(flags&1) && a≤entry<a+s` across logical segments; no final-page lookup resets it after a later overlap. [mprotect documentation](https://man7.org/linux/man-pages/man2/mprotect.2.html) (Linux man-pages6.19 read2026-10-17) describes page-range changes, zero success and host/process dependencies such as READ_IMPLIES_EXEC. Accordingly last **requested** flags are calculable conditionally; exact effective R/W/X needs the actual kernel/CPU/personality/mapping results and matching phase, and no such receipt exists. Reaching Mapped conditionally means all preceding calls returned through their checked path and the metadata predicate passed. `ns/nr` are admitted record counts, not unique regions/targets, validated imports or executed instructions. Earlier failures can follow allocations/writes/protection changes; no transactional rollback is supplied.

## Bounded next decision and stop rule

Use this contract unchanged as a reference when deciding whether a loader consumer may treat pre-entry Mapped as exact image identity or executable readiness: **defer those stronger inferences**. The controlling missing premise is an attributable, authorized consumer-owned input/build/host identity and matched post-read, post-relocation and final-protection observation for the property it actually needs. The smallest permission discriminator is P2: distinguish any-exec logical containment from the last page request, then inspect actual effective page permissions only if separately authorized. For bytes, distinguish I1's returned count/error from I2/R5's final content. A mismatched phase, input or dependency blocks that inference; it does not justify more target runs.

Outcome branches for a separately authorized public synthetic observation: if stable input/error-free read and attributable post-read bytes agree, accept only that copy phase; if relocation differences match ordered records, accept only that transformation under the resolved-pointer/ABI premises; if final measured permissions match ordered requests, accept only that mapping/phase/host; if requests differ from executable-entry metadata, retain the predicate distinction; if setup/read/protect fails or identities/phases are absent, stop without entry inference. Passing any branch does not qualify entry execution, filesystem confinement, original asset/code identity, original ABI/fidelity or game behavior. No experiment is executed or commissioned here.

Stop this source-only package at frozen checked handoff, independent review, ordinary linked repair and same-reviewer affected recheck, then parent-authorized status integration for one unmerged PR. No source implementation change, source import, acquisition/generation of ELF/SELF/prepared-image/fixture bytes, upstream script/build execution, compiler oracle, mmap/syscall/native/runtime/GPU/device/UI/game test, reader retry, general loader survey, contact, spending or merge is authorized. Formats3–5, patches, full renderer, linked initialization/TLS and original validation remain outside scope. Unknowns also include actual P/sysconf result, host protections/personality, allocation placement/extent and failures, endian/compiler/dependency artifacts, caller bytes/order and runtime reachability.

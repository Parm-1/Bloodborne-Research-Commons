For this implementation, a normally returned successful start has already called each admitted job synchronously; it publishes a batch slot only afterward. ## Instance and parser contract

[AJM:367–435][ajm]: initialize reserves context IDs1–8; create needs a valid registered codec, nonnull output and nonzero low3 revision bits. Codec1 is selected ATRAC9; codec0/2 and other non1 values below24 hit `exit(21)` before context validation, rather than returning an ordinary unsupported-codec result. Format bits7–9 admit0 S16,1 S32,2 float; larger values fail and release the instance used flag. Channels-hint bits3–6 are stored but decoding channels come from codec info. Codec flags are the high32 bits; gapless-loop is bit10. The returned instance ID is slot `i | (1<<14)`. Destroy/run mask the low14 bits; `InstanceCodecType` reports bits14–18 without consulting live state. Neither high codec bits nor the number alone establish a live instance identity. Slots are reusable, scoped to the context, with no generation counter. Unregister clears registration but does not destroy existing instances; run does not recheck registration.

Builders [AJM:91–142][ajm] copy native chunk structs into caller-provided capacity, truncate uint64 buffer sizes to uint32, mask flags and truncate instance to20 header bits. Ordinary run without return-address uses64 bytes (8 job +16 input +8 flags +16 output +16 sideband); ordinary control uses48. Neither checks storage capacity or target span validity. Run flags preserve the low13 and sideband bits45–47; control preserves its selected mask. Inline rounds the declared uint32 payload to8 after copying the original uint64 size; it is not a general safe storage constructor.

Start checks size multiple8, context and a free global batch slot. It walks chunks, recognizes inline or a job, then parses fields. `parse_job` [258–275] accepts either flags identifier and remembers the last flags/control/output-control chunk, up to16 input and16 output runs. It does not distinguish a strongly typed control job from run by builder identity. Return-address chunks are skipped; malformed BatchError always sets job_return_addressNULL. The parser copies8/16-byte records without first checking remaining declared bytes, and can overshoot the job's declared end before returning success. The inline `continue` precedes `p>end`. Thus alignment8 and a positive declared job length are not a full storage or well-formedness proof. Huge forged sizes may already make pointer arithmetic undefined. This study constructs no malformed bytes. Its defined-C contrary M1 below supplies actual allocated storage separately from inconsistent declared metadata.

## Decoder and sideband result

Control reset clears cumulative samples, resets gapless state and recreates an initialized decoder; initialize copies4 config bytes only when an8-byte control segment remains ([AJM:145–168, 288–310][ajm]). Optional format/gapless/resample segments change cursor applicability. `at9_reset` releases the old handle, allocates a new one, calls init and copies info only on success; it does not check allocation before dependency dereference and failed reinit can leave stale `info`. Treat successful allocation/init and valid compatible info as premises. A four-byte configuration is not proof of successful/safe decode. RIFF parsing is a separate unchecked-length path [233–249]; all ordinary decode positives below turn codec-flag bit0 off and do not claim RIFF safety.

LibAtrac9 [API:8–31][lib] uses calloc/free and forwards init with output word length16. [Init:27–96][init] copies config, derives frame/channel/superframe info and links handle-internal state; it also writes global trig/Huffman/gradient tables. [Decode:17–65][decoder] initializes a bit reader, propagates unpack error before PCM conversion/bytesUsed assignment, then emits interleaved short samples and sets `bytesUsed=Position/8` on success. [Unpack:28–79][unpack] advances frame state and aligns blocks to8 bits; error paths need not roll state back. The wrapper does not make the decoder transactional or independently validate fidelity.

The dependency API has **no length argument**. Its bit reader has buffer/position only; [Bit reader:34–70][bits] eagerly reads2,3 or4 bytes even when fewer bits are needed, without an end check. AJM's `in_size >= superframe_remain` check is not proof that all dependency reads are in a live readable object or within declared logical input, nor that `used` is nonnegative and bounded. For multiple inputs, AJM mallocs exactly the sum and copies into it, with no null check or extra lookahead padding. A single input can have a larger backing object than its logical size; a split input's original backing padding does not survive joining. No universal safe-padding size or arbitrary-malformed-frame admission is established. Successful decoder return, bounded used and defined dependency execution are explicit conditional premises in D1, not measured facts or a blanket memory-safety claim. Config initialization itself uses that reader: the11-bit read at bit position16 and2-bit read at27 touch byte4 beyond the copied ConfigData[4] array subobject ([Init:39–68][init]). A larger enclosing handle allocation alone does not settle strict-C subobject access or compiler lowering. Safe full-path initialization is therefore not established here. P2/D1 require a **separately qualified dependency/compiler artifact that actually defines the required config and decode reads**, with its precise read footprint and lowering; none is supplied. They are decoder-bearing body implications only, not established feasible strict-C full-path positives at the source pin. P1/B1–B4 and the N2/M1 schedules bound to P1’s exact creation flags1 (codec_flags0) and ordinary run without input-control initialization instead exercise real setup/accounting/sideband producers without calling decoder initialization or decode. Independent review must assess the subobject interpretation and this phase boundary; no implementation/compiler repair is proposed.

Within [AJM:277–364][ajm], an adequately sized output-control begins with8-byte `{int32 result, int32 internal_result}` zeroed before validation. Invalid low14 slot sets fatal|invalid-parameter and returns before later fields. The statistics ID `0x80000` is special and zeroes remaining sideband without decoding. Ordinary flags_result accumulates not-initialized1, invalid-parameter4, partial-input8, room16, codec-error `0x40000000`, fatal `0x80000000`; start itself can still return0. High-bit signed representations depend on admitted native lowering. Decoder nonzero e becomes internal_result and fatal|codec-error; capacity failure before the call has internal0. A raw nonzero internal is not a consumed-byte count.

For an initialized job with nonzero input, before a frame AJM checks full needed output bytes (after skip/total cap) and at least remaining-superframe input. It can set both room and partial flags and then break, with no call. If flags_result already came from gapless control it also breaks. Zero input skips the loop entirely and can return result0 even uninitialized. Successful frame consumption advances by dependency `used`, then may skip remaining superframe bytes, including gapless drain. Thus input_consumed includes alignment/drain/header bytes on applicable paths, not only decoded payload. Input bytes read for lookahead need not equal bytesConsumed. One-frame mode stops after one at9_frame; multi-frame mode loops until a result flag, including a next-iteration partial flag after input exhaustion. Gapless drain errors can break its internal drain without propagating a new internal/result flag. Neither result0 nor frame count certifies every compressed byte's decode.

S16 conversion copies decoder shorts; float divides by32768. S32 instead evaluates `(int32_t)v << 16` [209–211]. A negative short such as-1 violates C11 signed-left-shift rules; there is no defined all-PCM S32 numeric-output guarantee. This is a limit, not an observed output or repaired decoder. D1 selects S16. Optional deinterleave rearranges samples within each frame, then output_write scatters sequentially across output chunks; split outputs are not inferred to be one persistent plane per channel.

After conversion `total_samples` accumulates **emitted samples per channel**, after gapless skip/cap, not bytes or lifetime decoded samples across resets. Requested sideband fields are appended in stream16, format24, gapless8, multi-frame8, codec-info16 order **only when each fits**; a skipped large field does not advance the cursor, so later small fields may still fit. Stream is this job's int32 consumed/written differences and cumulative uint64 samples. Restrict numeric positives to representable int32 counts; no general large-count cast portability follows. Multi-frame `frames` increments even when at9_frame fails, so it is an attempt count, while global frames_decoded increments only after a successful primary decode (drain successes are not counted there). Counters and flags are not acoustic quality measurements.

## Phase, identity and lifetime

[AJM:436–477][ajm] holds the one recursive global mutex across parse/run, then writes `{used1, context id, canceled0}`, increments batches_run and writes slot+1 to the caller before unlock/return0. API0 means parsing reached publication; a well-formed invalid-instance job or decoder-error job still publishes. Out is not checked for null; error is only populated on the explicit malformed branch, not cleared on success or most other failures. No batch slot contains job pointers, decoded bytes or retained error. A later malformed job returns before publication yet earlier jobs' PCM, sideband and instance changes remain. There is no rollback.

Wait ignores timeout and BatchError, validates a currently live context and an occupied global slot1–256, optionally returns cancelled if its stored flag were set, then clears used. It does **not** compare stored Batch.context with supplied context. Cancel makes the same validation but mutates nothing, including canceled; the inspected public producer always initializes canceled0 and never sets it1. No ordinary public cancel→cancelled-wait path is established. Finalize releases handles and context storage but leaves batches unchanged. Destroy frees one handle and zeroes its instance. Context/instance/batch numbers can all be reused without generation identity; context recreation does not identify the earlier allocation. Occupied slots can remain after finalize, and another live context can retire them. An empty successful batch can consume a slot without running any job;256 unretired successes exhaust slots even though all work was processed.

Normal start return closes the selected synchronous parser/control/input reads and output writes **if** the call returned normally under valid memory/decoder/host premises. It is not a guest allocation-owner reuse protocol, a fence for unrelated threads, or proof no other reader exists. Builders read/copy their arguments during builder calls; command buffer and pointed input/control/output/sideband storage must stay valid and correctly aligned as actually accessed through start. One input is read directly; split inputs are copied into a temporary freed before run_job returns. No guest buffer pointer is retained in Batch or persistent Instance on the selected non-RIFF path; decoder config is copied and handle state persists until reset/destroy/finalize. No later wait/cancel needs those selected guest job buffers. Ownership still requires ordering against caller writers, other jobs/readers and any later sink consumer. There is no `runtime_memory_note_write`, `note_cpu_write`, `prepare_cpu_write`, AudioOut submit or notification call in runtime_ajm.c; declaration elsewhere does not create one.

The mutex is not a blanket thread-safety claim. Initialize publishes its out and re-reads contexts[i] after unlock, create's trace function is before lock, memory-register reads context without lock, and report reads plain counters without lock. Trace's lazy plain state can race between paths; report/counter accesses can race with processing. Decoder initialization writes shared tables that external direct dependency users could touch. The positives use a single externally ordered caller, no concurrent finalize/diagnostics/trace/env changes or direct decoder use, successful mutex operations and nonoverlapping live storage. Other threads require their own synchronization proof. Official [POSIX.1-2017 recursive mutex description reproduced by man7](https://man7.org/linux/man-pages/man3/pthread_mutex_lock.3p.html) supports conditional host lock behavior; this source checks no lock/unlock status, and the GNU static initializer is host-specific. Official [C11 draft N1570](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf) §§5.1.2.4,6.3.2.3,6.5.6,6.5.7,7.24.2.1 supplies race, alignment, object-bounds, shift and copy constraints. These three separately consulted mutable primary descriptions (checked2026-10-16, exact bytes not frozen) are not installed libc/compiler/kernel artifacts or original-platform proof.

## Producer and observation phases

1. `runtime_net_configure` copies supplied NUL-terminated strings (or empty strings for null) into static arrays: folder `PATH_MAX`, serial16, title128, version16. `snprintf` bounds/truncates bytes; its return is ignored. The caller need only keep source strings valid during each valid copy, but these arrays are mutable shared state, not a generation snapshot. No configured flag or identity validation is added. With no configure call they start empty. The selected probe call uses local identity arrays after source-described SFO reads when app0 is nonnull; read results are ignored at that call site. No actual SFO was read here ([net17–21][net], [probe372–382][probe]).
2. `runtime_net_enabled` caches exactly first-character `'1'` on its first call. A later environment change does not update that sequential cached result. Eligibility is a decoded-symbol prefix test, with the three local prefix exclusions applied after the online prefixes. A null/unknown decoded name is ineligible. The exact scoped string must first be found by `runtime_symbol`; a matching direct module prefix alone cannot bypass that runtime gate ([net24–40,84–91][net], [runtime263–278][runtime]). Mask0x1 (bit index0) is necessary to enter the general runtime resolver;0x2 alone fails. `is_data` follows a different path, and earlier resolvers can win. Admission is not binding or invocation ([runtime204–248][runtime]).
3. On the first eligible enabled request, `module_resolve` sets plain static `tried=1` **before** obtaining path, loading, resolving exports or initializing. A nonempty `BB_NET_MODULE` is copied/truncated to a stack path; otherwise it derives `gpu/libbbnet.so` beside `/proc/self/exe`. A failed readlink or dlopen leaves cached resolve null. Both exports are queried; `!init || !found || init(&host)!=0` short-circuits, so a null export prevents calling init. Nonnull export pointers are cast to header function types without a type/artifact handshake. Only a normal init0 after two nonnull exports stores `resolve=found`. Subsequent calls return that cached pointer or null with no retry, path refresh or reset ([net44–81][net]).
4. The stack `const BbNetHost host` contains version1, pointers to the four static arrays and the runtime spawn/join callbacks. The selected `bbnet_init` rejects null host, wrong version or either null callback **before** copying or configuring. Otherwise `g_host=*host` copies the struct by value; Configure then runs, followed by seventeen RegisterLib calls, a vector-length diagnostic and return0. There is no post-admission explicit nonzero-return branch and no catch/rollback in this body. Normal return of every invoked operation is a premise, not guaranteed. A different module supplied through the loader may return nonzero after its own side effects; that loader countercase is not a reached failure branch of this selected implementation ([abi13–35][abi], [glue487–515][glue]).
5. Configure's SetGame assigns `std::string` serial/title/version and `std::filesystem::path` folder into ElfInfo, sets initialized, and replaces its NP-ID vector from a source-described read of `folder/sce_sys/npbind.dat`. The helper opens/reads/parses that path. Its comments about file format are not game-file validation. The diagnostic can print missing IDs while init still normally returns0. `IsShadNetEnabled` is a separate cached flag plus session-disable state; its Flag also admits first-character y/t, unlike the runtime gate. No actual configuration or service was inspected ([glue411–455][glue], [elf63–79,102–119,145–159][elf], [settings14–18,78–93][settings]).
6. Registration is not necessarily passive address insertion. NpManager RegisterLib registers a state callback then calls NpHandler Initialize; NpWebApi RegisterLib registers a drain callback. These are exact opaque dependency boundaries here: no full Initialize, service, HTTP, authentication, account, network or callback implementation audit follows. Their completion, failure/exception behavior, side effects, synchronization and teardown remain unknown. A falling-back import does not certify their rollback ([regnp1205–1218][regnp], [regweb869–872][regweb]).
7. `LIB_FUNCTION`/`LIB_OBJ` drop library version; AddSymbol ignores library/module/type and appends an owned `std::string` NID plus a numeric address to `g_symbols`. Direct bbnet_resolve scans from the beginning, compares NID length and bytes before the first `#`, and returns the first matching address, or0. It does not compare suffix identities, classify function versus object, validate address/code or dispatch a service call. A first matching raw address0 stops lookup rather than trying a later duplicate. The vector-length log counts records including duplicates, not implemented or usable functions. The selected socket registration is a concrete producer of the known `Q4qBuN-c0ZM` NID; its implementation is outside this dossier ([libs18–22][libs], [glue460–484][glue], [regnet1949–1951][regnet], [imports145–146][imports]).
8. The runtime invokes the cached module resolver with the **original scoped name**. A zero result reaches the existing offline table; nonzero wins at this services stage. This is address selection only. Later call ABI, prerequisites, semantic correctness and service readiness are independent. When the offline table also yields0, later general resolvers may be considered; fallback is not universal resolution ([net84–91][net], [services470–476][services], [runtime247–261][runtime]).

## ABI and ownership contract

`BbNetHost` declares, in order, `uint32_t abi`, four `const char*` fields app0/serial/title/app_ver, then two function pointers. Spawn returns int32, takes void** output, a `void* (sysv_abi *)(void*)` entry, void* argument, uint64 stack_size and const char* name; join returns int32 and takes void* thread plus void** result. The header specifies0 or positive errno for these callbacks. Init is `int (*)(const BbNetHost*)`; resolve is `uintptr_t (*)(const char*)`. C linkage avoids C++ name mangling; exported C names and version1 do not validate binary layout, function prototype or installed ABI. Outer callbacks/init/resolve use the host default convention in these declarations; only the guest entry is explicitly sysv_abi. The runtime ABI macro matches that guest entry. If a consumer supplies the conventional Linux x86-64 premise of 8-byte data/function pointers and alignment8, expected host field offsets are0,8,16,24,32,40,48 and sizeof56. This is a conditional layout calculation, not compiler/native evidence. There is no size field, packing directive, static layout assertion, callback capability negotiation, generation, destructor or shutdown member ([abi][abi], [rh][rh]). A forged version1 or nonnull wrong pointer is not compatibility proof. Direct bbnet_resolve requires a readable nonnull NUL-terminated name; it has no null-name rejection before strchr. An invalid nonnull/undersized host or wrong callback prototype is outside the safe rejection cases.

| Object/value | Producer and retained identity | Lifetime supported by the selected source |
|---|---|---|
| Caller configuration strings | runtime configure copies bytes to static arrays | original caller storage may end after valid ordered copy; copy can truncate and is not semantic validation |
| Stack host struct | loader populates; selected init copies by value into global g_host | original stack struct may end after synchronous init returns; a different module must separately meet this nonretention premise |
| g_host string pointers | shallow pointer copies into static arrays in ordinary loader route | pointees are borrowed and can change through later configure; arbitrary direct-init callers must keep storage live for any covered read; no automatic ownership transfer |
| ElfInfo identity/path/ID vector | separate value assignments and returned vector in SetGame | independent owned storage, can remain old after runtime arrays change; repeated init replaces identity, not a generation-safe context |
| g_host spawn/join pointers | shallow function-pointer copy; wrappers read current globals on every call | nonnull admits, never leases callback/runtime code or enforces ABI/lifetime; later direct init can replace callbacks used by old module state |
| g_symbols entries | AddSymbol copies NID, appends numeric address, no clear in selected init | input NID source need not remain for a copied entry; addresses are values, not leases for code/data/arguments or context |
| dlopen handle | local pointer discarded on all exits after successful acquisition | selected loader never calls dlclose or retains a handle for shutdown, success or missing-export/init-failure paths; its acquired loader reference is unreleased under the described loader API |

The only g_host consumers in the inspected glue outside init are the spawn/join wrappers; retained string fields do not establish a later string read. Retaining a loader reference is not a complete code/data lifetime protocol and is not proof that every dependency/context/worker remains valid. RTLD_LOCAL limits later symbol exposure; it is neither a separate namespace nor a sandbox. RTLD_NOW forces load-time resolution under the described API, not logical initialization or service readiness. Loading can invoke constructors before bbnet_init; null init/found does not establish absence of prior side effects. dlsym may find names in dependency objects and null can have several meanings; the source only checks pointer truth, not dlerror after each query. No exact installed ELF/export/dependency/constructor artifact was observed.

The module create wrapper forwards to `g_host.thread_spawn`, using stack0 without attr and name `np` if null. Join forwards to current `g_host.thread_join`. In the ordinary runtime path spawn creates a guest-thread record/TCB/TLS, stores entry/argument, publishes handle before host create; return0 is earlier than entry completion. Join's selected wrapper translates the SCE error low16 to positive errno; successful matching host join is the endpoint for that host thread under the existing contract, not all callbacks, queued work, descendants, module state or network activity. Records/TLS are retained in those selected paths. Actual module worker creation, callback code/argument ownership, join ordering and drain/shutdown use are unknown. This does not open a full thread/unwind/cancellation campaign ([glue280–288][glue], [thread220–285,314–335][thread]).

## Reentry, repeated initialization and concurrency

For sequential synchronous reentry during the **first** attempt, tried is already1 but resolve stillnull: a reentrant eligible lookup returns0/falls back instead of retrying init or waiting. Ordinary later lookup after successful publication uses the cached resolver. This is a conditional schedule, not an observed dependency/constructor reentry. The guard is a plain int and pointer, not an atomic once primitive; cached enabled, configuration arrays, g_host and g_symbols also have no synchronization in these selected bodies. Serialize setup, first lookup, configure/init and vector mutation against readers under a valid external protocol. Host dlopen thread safety does not supply it. No outcome is predicted for conflicting unsynchronized accesses.

The loader normally calls init only once per such sequential attempt. Direct callers can invoke exported bbnet_init repeatedly: each admitted normal call replaces g_host/ElfInfo and invokes registrations again, with no g_symbols clear/deduplication/initialized guard. Each reached AddSymbol appends; existing matching entries still win over appended entries. Repeated state-callback registration/Initialize effects are opaque, not assumed idempotent or duplicate-safe. An old numeric function address need not imply an old context: calls can read overwritten global host/config state. There is no context handle/generation in the resolve API, no per-caller ownership, and no safe reload/reconfigure/reclamation protocol established by an address or init0.

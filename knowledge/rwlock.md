## Common contract premises

All positive implications below require valid/live/aligned typed caller slot and accessed attr/deadline backing, applicable pointer/integer/function conversion and SysV ABI, native initialization before operations that require it, successful ignored registry mutex operations, live pthread identities, complete wrapper-only use, ordered external slot/alias mutation, nonwrapping retention counters and normal cleanup without cancellation/fault/nonlocal exit. **Caller handle and alias slots must be disjoint from wrapper-owned Rwlock, Holder, registry and native-object storage. Accessed attribute/deadline bytes must remain readable and stable, without concurrent mutation across their reads.** Registry locking protects the selected internal mechanism; it neither validates this nonoverlap nor snapshots or synchronizes caller-owned input bytes. A path that never accesses a deadline, including timed try0 with NULL, imposes no deadline-read requirement. Host-success cases additionally assume the stated valid host operation actually succeeds; no execution outcome is asserted.

Native acquisition/release and native-object retention alone do not qualify protected application data. Claims about that data additionally require its relevant readers, writers and lifetime owners to follow a cooperating consumer access/lifetime protocol. The wrapper stores no such protocol, and retiring its native object does not retire caller data or storage. Initialized member operations may contend within the local guard under these common premises; external reinit/storage reclamation needs its own ordering.

R1’s source-only exclusion witness is a caller output slot designating an internal Rwlock next field: create_locked inserts the new allocation before writing through out, so this overlap can corrupt internal links despite native init0 and registry locking. It is excluded by the disjoint-slot premise, never an expected-error positive. Likewise, the busy timed path repeatedly reads nanoseconds and then constructs the deadline from seconds/nanoseconds outside registry_lock; a concurrent unsynchronized writer supplies no defined positive. These are premise countermodels, not compiled or executed fixtures. [Review r1](../docs/reviews/BRC-RWLOCK-01-REVIEW-r1.md) and [repair r2](../docs/reviews/BRC-RWLOCK-01-AUTHOR-r2.md) preserve the finding and response; no source/API re-audit or new case ID is added.

## Producer, storage and callable route

[Producer11–62](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_rwlock.c#L11-L62): caller supplies a writable `Rwlock **` slot. A separately calloc-allocated Rwlock contains the native pthread rwlock, a linked Holder list, unsigned inflight and registry link. Each Holder stores pthread_t, unsigned readers/writer/pending and next. Global registry and all selected object bookkeeping/counters are accessed under one statically initialized native mutex. Host blocking acquisition happens outside that mutex, allowing another wrapper thread to unlock. Registry address comparison happens before dereferencing a candidate Rwlock; arbitrary nonmember values are rejected, assuming the slot itself is valid to read. Pointer membership is not a storage-span validator or an allocation-generation identifier.

Explicit init never reads `*out`. NULL out or non-NULL attr with NULL `*attr` gives EINVAL. A non-NULL attr whose readable `*attr` is non-NULL prints STOP and exits21, without applying any attribute. NULL attr creates a new native object with `pthread_rwlock_init(...,NULL)`; name is ignored without a read. The wrapper configures no priority, sharing, fairness, recursion kind or clock attribute. Host default attributes are used. Allocation/native-init failure does not publish a new pointer; native-init failure frees the new allocation. The old slot contents are therefore untouched on failure, even though explicit init permits initially uninitialized output storage. On success it inserts the new allocation, writes the slot and increments created. Reinitializing a still-live slot allocates another native object rather than reinitializing the old native storage; it can orphan the old registered object. A previously copied alias can still name that old object. This is not a valid-host-use violation from calling native init twice on one native object: the allocation is different.

[Resolver146–166](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_rwlock.c#L146-L166) selects nine exact `#p#J` imports:

## Admission, ownership and observation phases

[Acquire63–117](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_rwlock.c#L63-L117): NULL slot pointer gives EINVAL. Under registry lock, raw slot0 lazily creates a default native object; nonzero values must match a registry address. Raw1 is not lazy initialization. Holder identity is `pthread_equal(stored,pthread_self())`, not guest thread handle or a numeric thread comparison. Existing writer ownership forbids all six acquisition forms; existing read ownership forbids write forms. Try variants give EBUSY; blocking and timed variants give EDEADLK before host acquisition or deadline read. Thus there is no recursive writer, downgrade, upgrade or automatic read-release path. Existing readers may acquire another read, subject to host outcome and the UINT_MAX reader guard (EAGAIN). New Holder allocation can fail ENOMEM after lazy native creation has already succeeded; acquisition failure need not undo object creation.

| Observation phase | Wrapper state and native implication |
|---|---|
| Before admission | No retention from this call. Another thread can retire an idle object before this call reaches registry lookup; a valid slot stays caller-owned storage |
| Admitted, registry mutex released | Incremented r.inflight and this h.pending retain both records. h.readers/h.writer are previous completed acquisitions; pending is not yet proof of a blocked wait |
| Native attempt/wait, or host return before bookkeeping | Pending/inflight remain set through try success, blocking wait, deadline validation and native return. Native success can already own the lock while h has no recorded owner |
| Bookkeeping under registry mutex | Decrement inflight/pending; only host0 increments readers or sets writer1 and increments cumulative reads/writes. Failed attempt adds no ownership; prune frees only when readers/writer/pending all0 |
| Registry mutex released, C return pending | No more r/h dereference in acquire: only error(e) remains. On failed acquisition the last Holder may already be pruned and destroy can proceed before that caller's error return. On success recorded ownership still prevents destruction |

Under correct host contracts, successful read acquisition permits concurrent readers, while a successful write acquisition excludes other native readers/writers. Default host policy determines admission when writers wait; source supplies no FIFO, writer/reader preference, bounded starvation or scheduling guarantee. Repeated reads require matching unlocks; allowing the request does not promise it cannot block behind a writer on every dependency. The self checks avoid selected same-object self-deadlocks; cross-object cycles and progress remain unproved. A try operation still waits for the registry mutex and may allocate/init; its native rwlock try is the nonblocking part, not a universal nonblocking wrapper guarantee. Timed entry likewise can spend unbounded time outside the host timed wait.

## Deadline and result domains

[Timed path93–110](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_rwlock.c#L93-L110) first invokes native tryread/trywrite. Only `timed && e==EBUSY` reads the deadline. NULL or nanoseconds outside0..999999999 then yields EINVAL without native timed acquisition. On try0 the deadline pointer is never dereferenced or validated; a valid object with NULL or invalid-nanosecond deadline can return0 and own a lock. Other try errors, such as EAGAIN, also bypass deadline validation and are mapped after bookkeeping.

`GuestTime` has signed int64 seconds/nanoseconds. Busy valid-time path casts seconds to time_t and nanoseconds to long into a native timespec, then invokes `pthread_rwlock_timedrdlock/timedwrlock`. No wrapper clock sample, addition, microsecond conversion, relative interval, normalization, remainder write or seconds-range check exists. The separately cited timed APIs specify an absolute CLOCK_REALTIME deadline and allow immediate success rather than timeout. The host may acquire between busy try and timed call. Expired time therefore does not force a timeout if acquisition becomes immediate. Deadline representation/conversion, actual realtime behavior and elapsed duration need installed-host evidence. Negative/unrepresentable seconds have no added wrapper validation or qualified conversion contract; valid positives require representable values. This differs from sibling relative timed mutex/semaphore routes. No runtime_wait_note/clock call occurs in this file; inflight/pending and cumulative reports are not measured wait duration.

[Error27–41](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_rwlock.c#L27-L41) maps native or wrapper errno symbols to raw32 `0x80020000|code`: EPERM1, EDEADLK11, ENOMEM12, EBUSY16, EINVAL22, EAGAIN35, ETIMEDOUT60; zero maps0. These are int32 return values, not `-1`, host errno numbers, a POSIX low16 adapter or a proved SDK declaration. Unmapped errors print STOP and exit21 after any reached cleanup; there is no normal guest error return. All native registry mutex lock/unlock results are ignored. Conditional synchronization/lifetime reasoning requires these operations succeed; an ignored failure is not evidence that the registry was protected.

## Unlock, destruction and reconstruction

[Unlock118–130](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_rwlock.c#L118-L130): NULL slot or nonmember value gives EINVAL. A live member with no current-thread Holder ownership gives EPERM before host unlock. This is a meaningful defined wrapper rejection of a nonowner; invoking native unlock as a nonowner would instead violate the cited host precondition. Host unlock runs while registry mutex is held. Only host0 clears writer or decrements one reader and increments unlocks; host failure retains recorded ownership. prune retains any reader, writer or pending count. Successful release of one recursive read or one of several readers does not unlock the whole native rwlock; the last matching read release or writer release has the host release implication. No protected-data predicate, transaction or caller task completion is stored.

[Destroy131–145](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_rwlock.c#L131-L145): NULL slot gives EINVAL; raw0 returns0 unchanged without creating/destroying anything. Nonmember raw1/other values give EINVAL. A registered object with inflight nonzero **or any Holder** gives EBUSY without host destroy. The guard covers admitted blocked calls, immediate attempts, the native-success-before-bookkeeping gap, recorded readers/writers and a pending-only Holder. It is stronger than asking native destroy to reject a locked object; the cited POSIX API declares native destroy while held undefined, so such an invalid host call is not a normal-return positive.

With no inflight and no holders, a successful host destroy removes the registry link, frees Rwlock and writes pointer tombstone1 to only the passed slot, under the same mutex. Native destroy error leaves registry/slot/allocation intact. Assuming complete exclusive wrapper use and the premises below, the guard gives a local native-object retirement boundary: no admitted acquisition still references native/r/h and no wrapper-recorded owner remains. It does not wait for an acquisition not yet admitted, a failed acquire/unlock epilogue, arbitrary caller code, protected-data consumers, or thread termination. The caller's slot/deadline/data backing has its own lifetime. A thread can retain its own valid alias slot after destroy, but the pointed object has ended. A later lookup rejects that stale address if no registered object reuses it. The registry has no generation; allocation reuse could instead make the same address identify a different live object. No ABA event or unsafe concurrent use was observed.

Sequential explicit init after tombstone1 may publish a fresh object; lazy acquire on1 rejects. Writing0 to an otherwise safely retired slot enables lazy creation; it is not proof an old object was retired. Explicit init while old ownership exists leaves the old native object/Holder registered; unlock through the overwritten slot targets the new object and cannot release the old one, while an existing valid alias can. A leaked old entry is not automatically swept. No cancellation cleanup, thread-exit Holder removal, robust owner-death recovery, shutdown sweep or join appears here. A thread must close its owned operations/locks before its identity expires; pthread_equal on invalid thread IDs is outside the cited defined contract. Cancellation/nonlocal exit or forgotten unlock can prevent retirement; no forced-recovery normal result is claimed.

The four global size_t counters are protected by registry_lock in this selected file and report. created counts successful object creations, not live objects; reads/writes count completed successful acquisition bookkeeping, unlocks counts successful native releases. They are cumulative, have no generation/owner attribution and can wrap. inflight/pending are unsigned and increment without overflow checks; readers has a UINT_MAX check. This bounded contract assumes those retention increments do not wrap and every participating call returns through its cleanup. A raw pending1 does not distinguish blocked, pre-native, returned-success or deadline-validation phases. Cumulative counts cannot replace per-object ownership or host/thread endpoints.

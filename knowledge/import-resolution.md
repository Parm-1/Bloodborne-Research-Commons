# Scoped import selection and callable outcomes in bbport

Question: when does one import select a host function, a linked-image fallback, a callable placeholder or a failure, and what phase does the observation establish? Consumer: a runtime maintainer interpreting one exact import and relocation. This proposed topic is **SOURCE_INSPECTED**, 2026-10-13, at `deadinside28/bloodborne_pc@3c57da4198ad62039f63f33bfd205b9916518acf`. Independent review and human acceptance are pending. No source, script, build, boot image or runtime was executed; no original/game input was acquired. [RC-0018](../claims/RC-0018-import-selection.md) owns selection; [RC-0019](../claims/RC-0019-import-outcomes.md) owns observation limits. [Open consumer question](../frontiers/import-resolution.md).

## Inputs and selection contract

The inspected Linux build compiles `src/runtime*.c` with `probe.c`, links `libbbgpu`, and uses SysV guest function declarations; this is source configuration, not a built artifact identity ([build.sh lines 72-83](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/build.sh#L72-L83); [src/runtime.h lines 13-17](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime.h#L13-L17)). The Windows branches exist, but this study does not qualify Windows build or execution.

The preparation producer takes undefined symbol names literally, assigns import indices and emits kind 2 for symbol type 1 (object), kind 1 otherwise. It rejects nonzero function addends and data addends outside `[0,4096)` ([scripts/prepare.py lines 185-215](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/scripts/prepare.py#L185-L215)). The probe reads names as fixed 128-byte records and requires a NUL; import relocation `value` is an index, while kind 0 is image-relative. It requires a mapped eight-byte relocation target, kind at most 2, in-range indices, zero non-data addends and data addends below the actual host page size ([src/probe.c lines 471-497](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/probe.c#L471-L497)). These are syntactic/range checks, not a proof of correct symbol ABI, object extent or image origin.

The raw capability field has only one accepted bit. BBPROBE1 implies zero; later accepted formats read it and reject any other bit. `--strict-imports` defaults off and passes zero to `runtime_start`; otherwise the serialized value is passed. `native_libc` is true only for a linked format (BBPROBE3/4/5), non-strict mode and bit 0 set ([src/probe.c lines 400-458](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/probe.c#L400-L458)). `--cpu-only` suppresses graphics initialization, not the capability gate or all GPU-library registration; kernel event queues and AvPlayer are registered before boot loading ([gpu/shim/bbgpu.cpp lines 305-321](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/gpu/shim/bbgpu.cpp#L305-L321); [probe options and registration](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/probe.c#L340-L398)).

`runtime_start` stores the effective flags and, when bit 0 is set, initializes a random stack canary; failure exits 1, and its low byte is cleared ([src/runtime.c lines 70-85](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime.c#L70-L85)). The producer sets this bit from its inspection of a supplied libc's `_init_env` bytes, exactly one `C3` byte ([scripts/prepare.py lines 112-141](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/scripts/prepare.py#L112-L141); [scripts/prepare.py lines 233-249](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/scripts/prepare.py#L233-L249)). The probe does **not** recompute that inspection, compare a libc digest or authenticate the flag. The comment and printed “verified libc implementation” text in the host `_init_env` function are not an image receipt: the function increments a counter and returns ([runtime lines 103–107](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime.c#L103-L107)). There is no actual supplied libc or preparation result in this study.

For each import relocation, the probe initially selects an unresolved function trampoline (kind 1) or a protected data page plus addend (kind 2). It asks `runtime_resolve` first. Any nonzero result overrides a linked binding; only a zero result permits enabled linked fallback. Otherwise the initial trap address remains. Selection writes eight pointer bytes into the image; it does not invoke the import ([src/probe.c lines 515-542](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/probe.c#L515-L542)).

### Matching is different at three host layers

1. `runtime_resolve` returns zero immediately unless effective bit 0 is set. In data mode it accepts only two exact strings, for the stack canary and the `Need_sceLibcInternal` marker, then returns; it never falls through to function resolvers. Function mode checks exact scoped strings for selected libc helpers, then queries mutex, thread, content, time, sema, rwlock, memory, kernel, services, AJM, audio, pad, RTC, savedata and file in that order, returning the first nonzero address, then GPU fallback ([src/runtime.c lines 204-282](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime.c#L204-L282)). No general duplicate/export-collision audit is claimed.
2. `runtime_symbol` matches the **whole** string to the first row of `import_names.inc`. `runtime_lookup` then matches the decoded name to the first exact name in the caller's export table ([src/runtime.c lines 204-282](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime.c#L204-L282)). This table is used for binding as well as diagnostic naming despite its “diagnostics only” header ([src/import_names.inc lines 1-15](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/import_names.inc#L1-L15)); a known name alone is not an export. Neither plain function names nor arbitrary same-NID suffixes automatically match this path. The table also has literal `NID#library-name` spellings for selected linked imports ([src/import_names.inc lines 739-750](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/import_names.inc#L739-L750)). The source comment that equal symbol names mean equal contracts across libraries is an author's rationale; this lookup does not independently validate ABI or semantics.
3. GPU fallback strips at the **first** `#` and matches that prefix's length and bytes against the first registered NID; suffix library/module identity is not compared ([gpu/shim/bbgpu.cpp lines 305-321](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/gpu/shim/bbgpu.cpp#L305-L321)). Registration stores library/module strings, but the shim drops `libversion` at the macro boundary and ignores symbol type in `AddSymbol` ([gpu/shim/core/libraries/libs.h lines 8-20](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/gpu/shim/core/libraries/libs.h#L8-L20); [gpu/shim/bbgpu.cpp lines 64-77](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/gpu/shim/bbgpu.cpp#L64-L77)). This differs from scoped runtime matching. A returned GPU address does not establish that graphics initialization or the selected function's prerequisites succeeded. The count reported by `bbgpu_symbol_count` is vector length, not a semantic implementation count ([lines 342–344](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/gpu/shim/bbgpu.cpp#L342-L344)).

Within the services resolver on Linux, online resolution precedes the offline name table ([src/runtime_services.c lines 470-476](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_services.c#L470-L476)). `BB_ONLINE` is cached from whether its first character is `1`; an eligible decoded name has a `sceNet`, `sceNp`, `sceHttp` or `sceSsl` prefix except trophy/commerce/profile prefixes. First lookup tries the configured or default `libbbnet.so`, requires init/resolve exports and successful initialization, and calls its resolver with the original scoped string. Disabled, ineligible, missing, failed initialization or zero online address permits the offline table ([src/runtime_net.c lines 24-91](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_net.c#L24-L91)). This establishes the fallback selection, not the external module's function correctness or all of its ABI/lifecycle behavior.

### Linked producer and consumer are separate

For BBPROBE5, `link_modules.py` decodes library/module suffix IDs through dynamic tables: each identity contains a name and a 16-bit version. Matching uses `(NID, library identity, module identity)`, so equal NID text alone is normally insufficient ([scripts/link_modules.py lines 43-65](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/scripts/link_modules.py#L43-L65)). New import identities use main-program suffix spelling only when both identities match; otherwise they are emitted as `NID#library-name`, losing version/module information from the host lookup string ([scripts/link_modules.py lines 109-123](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/scripts/link_modules.py#L109-L123)). The producer retains the full tuple for its own linked binding decision.

Export candidates must be defined, global/weak, scoped and object/function typed, with their declared extent mapped; duplicate full identities fail. The one exception: when an exact export is absent for `libSceLibcInternal`, a unique same-NID candidate under library name `libc` is used, without requiring equality of that candidate's module or version. Zero or multiple candidates leave it unresolved ([scripts/link_modules.py lines 182-208](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/scripts/link_modules.py#L125-L208)). The same-functions explanation in the docstring is PROJECT_REPORTED; it is not demonstrated ABI equivalence. Legacy `link_libc.py` has exact tuple matching and uses `libc:original-spelling` for new identities; that spelling is not the BBPROBE5 `NID#library-name` form ([scripts/link_libc.py lines 105-159](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/scripts/link_libc.py#L97-L159)).

BBPROBE5 serializes binding triples `(import index, image offset, kind)` and a report with native-binding and unresolved counts ([scripts/link_modules.py lines 216-239](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/scripts/link_modules.py#L216-L239)). For normal valid producer output, linked modules are placed after a positive-sized main image and binding offsets are nonzero, with one binding emitted per indexed identity ([producer placement and binding emission](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/scripts/link_modules.py#L95-L206)). The raw probe consumer checks index, kind 1/2, containment in a declared module and whether `bindings[index]` already holds a nonzero address. It does not explicitly reject address zero: a permitted zero-base module can contain it, and storing it leaves the duplicate sentinel clear. A subsequent entry at that same index can therefore pass after a zero entry. Later, zero addresses are skipped as absent; nonzero addresses require mapped coverage and executable placement for kind 1 ([src/probe.c lines 400-458](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/probe.c#L400-L458); [src/probe.c lines 471-497](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/probe.c#L471-L497)). It does not redo NID/library/module matching. On the selected fallback only, binding kind must equal relocation kind and coverage must include `addend+1`, then the pointer is `image+binding offset+addend` ([src/probe.c lines 515-542](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/probe.c#L515-L542)). Range checks do not validate the whole later access width or a data object's extent. A producer binding count is not the count of host functions reached; host selection can override those bindings.

## What a phase establishes

Import-name recognition is diagnostic/table identity only. Pointer selection is a relocation-time binding decision; it is not call dispatch. The “Mapped … applied relocations” line is printed only after entry/segment protection checks, but supplies no per-import implementation receipt. Enabled linked initializers run in link order and nonzero return fails; their successful returns do not validate every bound export. The “Entering original …” line and `entered_game=1` occur **before** the entry call, and on Linux before stack allocation can fail. A flag or printed line alone cannot demonstrate executed guest instructions ([src/probe.c lines 545-589](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/probe.c#L545-L589)). The unsupported function trap demonstrates a reached call to that trap, with the source's phase flag; it does not establish complete initialization or gameplay ([src/probe.c lines 115-129](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/probe.c#L115-L129)).

To establish implementation dispatch, a future authorized non-game check needs the exact scoped name, raw relocation kind/index/addend, effective capability and strict setting, format/binding metadata, registered tables and attributable selected pointer/call. To establish feature success it additionally needs the selected function's state/inputs, returned error and actual output/side effect. Execution correctness needs an independent expected contract and falsifier. This source study supplies none of those run records.

Reuse: **KNOWLEDGE_REFERENCE**, for distinguishing selection from feature behavior and choosing one discriminating observation. Defer any runtime/game or general ABI qualification. Stop this trace at this source checkpoint; revisit only for affected review findings or an exact consumer import/configuration with a decision-changing public-source question. No broad loader/kernel survey, image acquisition, build or script execution is implied.

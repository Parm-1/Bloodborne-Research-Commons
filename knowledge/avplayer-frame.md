# AvPlayer returned video pointer: retain, recycle, destroy

**2026-10-17 — Proposed/unmerged SOURCE_INSPECTED, BRC-AVPLAYER-FRAME-01, Batch04 [Issue #24](https://github.com/Parm-1/Bloodborne-Research-Commons/issues/24). Independent source review, root acceptance and owner editorial acceptance/merge pending.** [RC-0056](../claims/RC-0056-avplayer-frame-output.md), [RC-0057](../claims/RC-0057-avplayer-frame-lifetime.md), [frontier](../frontiers/avplayer-frame.md), [author r1](../docs/reviews/BRC-AVPLAYER-FRAME-01-AUTHOR-r1.md).

Consumer: a media/runtime maintainer deciding whether to copy the returned pixels before advancing the player, or supply a separately justified reader-completion and retention mechanism. The bounded answer is a borrowed callback-allocated texture buffer. Metadata is copied; ownership is retained in the source's current frame, then recycled on the next successful video getter. No explicit release token or external CPU/GPU reader acknowledgement participates in that transition. This is a conditional source contract, not a qualified playback implementation.

## Admission and metadata output

CMake selects the AvPlayer cpp files and video-utils, searches shim before shadps4, links the five named pkg-config FFmpeg modules, and does not constrain their version here. `bbgpu_register_kernel` calls AvPlayer registration. The registration stores function addresses for `o3+RWnHViSg` (legacy), `JdksQu8pNdQ` (Ex), `ZC17w3vB5Lo` (Stop) and `NkJwDzKmIlw` (Close). Shim resolution compares the NID prefix before `#`, returning the first matching stored address; module/library/version are not validated by this lookup. Registration/resolution is availability, not a call or evidence of a usable player.

The handle is an `AvPlayer*`; getters use bool and `PS4_SYSV_ABI` (`sysv_abi`). Wrappers reject only null handle/output, then dereference; a non-null stale pointer is not validated. Output storage must be correctly typed, aligned, writable and live with the matching build/callback ABI. The impl checks state presence; state checks source presence under a **shared** source lock. The source overload tests its own `IsActive()` and pause flag, then nonempty video-frame queue; in Default sync it rejects front timestamp strictly greater than CurrentTime. Equality passes; every non-Default enum value bypasses that comparison because the setter merely stores it. The source getter does not call state `IsActive()`'s extra Stop/Error test.

Default clock admission compares producer milliseconds against a source clock: no start gives zero; EOF/inactive returns duration; other inactive gives zero; audio-present uses last handed-out audio timestamp plus elapsed host time, otherwise start-time elapsed clamped to duration. These are scheduling computations, not audio-played, presentation or reader-completion receipts. `HasFrames` tests video **packets** greater than a requested count or EOF; Ready follows stream discovery. Neither establishes a decoded video output.

At success the Ex getter copies `frame->info` into caller output and moves the popped Frame into current ownership. Legacy delegates to Ex, zeroes its smaller output only after success, then copies timestamp/pointer/aspect/width/height. It omits pitch/crops/bit-depth. False paths before success leave caller metadata untouched: an old non-null output can therefore remain while no new frame was returned. Legacy and Ex describe alternative calls for a given queued frame; successive successful calls advance and can return different generations.

## Producer, extents and byte identity

Supplied sufficient premises: one live stable player/source/start generation; valid initialized callback table and callback object; successful nonoverlapping allocations of requested extent/alignment and matching deallocators that release them; live readable decoded planes with positive even dimensions, valid NV12 layout and representable arithmetic; stable stream/time-base state; successful required conversion/allocation; no external frees/writes; and actual happens-before ordering of conflicting operations. No actual AVFrame, encoded/media input or callback allocation was supplied or executed here.

Init copies allocator callbacks into the source and clamps requested output framebuffer count to 2..16. Start allocates that many texture buffers, alignment256, capacity `Align64(codec_width) * Align16(codec_height) * 3 / 2`, using u32 arithmetic before storage in u64. Do not infer safe capacity from type width: dimensions/conversions/products must be valid and nonoverflowing. Buffers retain a reference to the source allocator table. Its stubs carry the player as object pointer and forward to the original callback and object pointer; those original objects/code must outlive every callback, including teardown. Null callback checks establish neither this lifetime nor a valid returned allocation. The selected shim Thread::Run calls runtime_thread_attach_host("bb:hle") before its function. The existing thread/TLS attachment contract is reused at its prior scope; that source call alone supplies no installed callback ABI or runtime attachment result.

The decoder obtains a packet, submits it, receives a decoded AVFrame, pops a free GuestBuffer, converts non-NV12 through a cached swscale context, and copies into the GuestBuffer before enqueueing a Frame. Success is a supplied premise: this bounded trace does not prove decoding, draining, all error handling, reconfiguration or swscale-cache validity. Conversion ignores the frame-buffer allocation result and checks sws_scale only for a negative result; the candidate does not promote those calls into verified output. The returned `p_data` is exactly `buffer.GetBuffer()`, not a retained FFmpeg plane or AVBufferRef. Copy is synchronous before enqueue; later destruction/unref of the temporary AVFrame does not itself free that independent GuestBuffer.

For decoded W,H, CopyNV12Data uses P=Align64(W), A=Align16(H), checks `P*A*3/2 <= capacity` with ASSERT, luma base p and chroma base `p+P*A`. When W!=P it copies W bytes per luma row and W per H/2 chroma rows using source linesizes, then repeats the last corresponding source row vertically into the aligned height. Horizontal padding P-W is untouched. When W==P it bulk-copies W*H and W*H/2 bytes, **ignoring source linesizes** for those initial rows; a valid padded/negative-stride AVFrame alone is insufficient to establish faithful pixels on that branch. Positives require tightly packed positive source planes there. Vertical-extension source accesses still require valid strides/rows. Neither ASSERT nor a supplied capacity proves the raw source spans readable, arithmetic nonoverflowing or the allocator honest; no deterministic recoverable error is predicted for violated premises.

Metadata uses width=Align16(W), height=A, pitch=P, eight-bit depths, sample aspect ratio, raw left/top crop and right crop plus P-W, bottom crop plus A-H. It is not a byte-count field or a promise that every capacity byte was initialized. Invalidation is called with `Align16(W)*A*3/2`, which can be smaller than the pitch-based capacity; shim forwards to rasterizer only when present. This study does not audit renderer invalidation or derive a reader fence from that call. Crop narrowing/underflow/overflow and dynamic dimension changes are outside the positive premise. The source allocation geometry comes from codec dimensions; copy geometry comes from each decoded frame, so equality/fit must be supplied rather than assumed.

## Current retention, recycle and shutdown

On a successful getter, **before** Pop/output/current replacement, old current's GuestBuffer is moved into the free pool, current is reset, and the buffer CV is notified. The decoder may subsequently pop and overwrite that allocation for another generation; old pixel pointers and copied old metadata have no retained-reader lease. Caller reads must finish, or a complete owned copy must be made, before permitting that recycle. An asynchronous consumer needs its own attributable completion/retention contract; the getter does not wait for it. The next getter's return is too late to serve as a universal old-buffer safety boundary.

Under supplied serialization and a live same source, inactive/paused/empty/future-Default rejection occurs before old recycle: that **particular false call** retains current and does not alter output. This excludes intervening success, Stop/Close/destruction/start or external allocator actions. EOF/inactive ignores current frames in its queue/packet formula, so inactive does not imply current deallocation. State's EOF-derived StateStop event only emits an event; it does not call source Stop there.

Queue Push/Clear lock; Size and Front do not. Pop tests Size before taking its mutex. State getters/Stop/Pause share the source lock; source GetVideoData does not take m_state_mutex, while Start/Stop do. Thus one caller, shared-lock presence or atomic state flags does not establish race freedom against decoder Push, another getter, Stop/Clear or changing clock/sync fields. Positives require actual ordering of these conflicting accesses, including background producers. No claimed runtime schedule demonstrates that premise. Concurrent getter/clear examples have no defined successful result prediction, and this package does not design a synchronization repair.

GuestBuffer move construction transfers reference, pointer, size and texture kind and nulls the old pointer. Move assignment swaps **only pointers**. The selected video route uses move construction through pool pop, value argument, Frame creation and queue moves. Getter resets old current before assigning its optional from the newly popped optional, so current is disengaged and constructs its Frame; this does not establish an active-to-active cross-allocator move assignment. All video-pool buffers of one stable start use the same allocator/kind/capacity. Pointer-only assignment is not a general sound ownership-transfer API across heterogeneous buffers, but that hypothetical mismatch is not presented as a reached defect. Destructor calls the selected deallocator once for a non-null buffer; this depends on the callback/allocation premises.

Source Stop first locks its state mutex. With no joinable tracked threads it returns false **before** current reset/queue clearing. Otherwise it resets custom streamer if present, calls Stop on video/audio/demux wrappers, resets current frames, clears pools/packets/queued frames, resets timing/pause/EOF, and returns true. Those buffer destructions invoke deallocation callbacks; Stop does not preserve escaped pointers. The wrapper requests stop then joins if joinable, except self-Join detaches. Decoder/demux tails themselves call Join; a detached/nonjoinable handle is not a completion receipt. Concurrent operations on thread objects, blocking I/O, self-detach and mutual joins are not qualified. The conditional clean Stop positive requires corresponding successful nonself joins or separately established completion of already-detached threads, no conflicting thread-object accesses and normal callback return; no universal termination guarantee is made.

State Stop can reject missing source/already-Stop; it can also fail SetState after source Stop has already freed buffers. Therefore a failed public Stop is not a preservation guarantee. Close deletes the raw handle. AvPlayer destroys its state before its original allocator data; state resets source under unique source lock before stopping its controller; source destructor calls Stop and then member destruction destroys retained current/queues even if Stop returned false. Source members holding buffers are destroyed before its allocator table. Under quiescent teardown premises, escaped pixel pointers have no surviving ownership after deallocation, even if numerical addresses recur. The unique source lock does not protect a caller after raw player deletion or a GPU reader. This is not a full deadlock/reentrancy/resource audit; arbitrary callback reentry and live detached work during destruction remain unqualified.

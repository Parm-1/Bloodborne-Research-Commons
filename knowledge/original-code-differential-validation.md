## Pipeline and eligible reference

BUILD: C++20; the selected target is inside `if(UNIX)`, not a qualified Windows test. CMake builds the test with the camera replacement and mouse assembly stubs, links `eboot_kit` and pthread, and supplies `2000`. The kit contains `eboot_kit.cpp`, ELF, memory, SHA-256 and TLS rewrite implementations; it does not link the full runtime importer or decomp installer. Test flags are `-fno-stack-protector -ffp-contract=off`; replacement source properties add `-mavx`. AVX x86-64/SysV and Linux-style kit facilities are prerequisites, not demonstrated portability. Global configure dependencies (including ZLIB and bundled libraries) still apply. [CMake build and flags](https://github.com/droogie/bbhost/blob/566184a74f071166299bb656c4af479e5bbe2771/CMakeLists.txt#L467-L488); [source flags](https://github.com/droogie/bbhost/blob/566184a74f071166299bb656c4af479e5bbe2771/CMakeLists.txt#L339-L342); [UNIX scope](https://github.com/droogie/bbhost/blob/566184a74f071166299bb656c4af479e5bbe2771/CMakeLists.txt#L381-L382)

IDENTITY/LOAD: `BBHOST_EBOOT` or the source-directory fallback is read and hashed against the named 1.09 SHA-256 (`941f887a562aae054fac35af8cc8f27cf075f3d4cc2e029fb5ae2a663aaa5ae7`). Missing/unreadable or wrong hash exits 77 before comparison. The loader reopens that path; the kit does not compare the loader's second-read hash to the first, so an authorized consumer must preserve the file through loading. ELF magic, x86-64, minimum VA zero, nonempty load span, SCE dynamic data and PT_DYNAMIC are checked. Segments are copied into zeroed memory plus a 4 MiB tail. Preferred `0x400000` is a mapping hint on Linux; relocated fallback or `BBHOST_SLIDE` at another base is rejected by the kit. Relative and absolute-64 relocations are applied; GLOB_DAT and JUMP_SLOT are bound; other general relocation types are counted rather than universally rejected. This is an exact-input helper, not a general malformed-ELF validator. [kit identity/load](https://github.com/droogie/bbhost/blob/566184a74f071166299bb656c4af479e5bbe2771/tests/decomp/eboot_kit.cpp#L95-L109); [load failure](https://github.com/droogie/bbhost/blob/566184a74f071166299bb656c4af479e5bbe2771/tests/decomp/eboot_kit.cpp#L181-L204) [ELF loader](https://github.com/droogie/bbhost/blob/566184a74f071166299bb656c4af479e5bbe2771/src/core/elf.cpp#L111-L338) [mapping](https://github.com/droogie/bbhost/blob/566184a74f071166299bb656c4af479e5bbe2771/src/core/memory.cpp#L17-L57)

ENVIRONMENT: default Linux GS mode is selected unless `BBHOST_TLS_GS` begins with `0`. Exact nine-byte FS-self-read patterns become GS-slot reads before text protection. The kit allocates zeroed `0x750` TLS plus TCB, sets self/magic, installs a zeroed TEB stand-in via `arch_prctl`, and sets MXCSR `0x9fc0` and x87 `0x037f` for both arms. It neither copies PT_TLS initialization data nor calls ELF entry/init/static constructors. The GS syscall result and several allocation/protection operations are not checked here; `stub()` does not check either `mprotect`, `bind()` directly writes GOT slots, and the test's patch `mprotect` calls also assume success. These are attempted setup operations, not observed successful TLS/page-protection receipts. In FS mode the kit allocates no TCB and does not switch FS: header promises must not qualify that alternate configuration. The reported completeness of the TLS pattern census is an upstream comment, not reproduced evidence. [TLS mode/rewrite](https://github.com/droogie/bbhost/blob/566184a74f071166299bb656c4af479e5bbe2771/src/core/tls_rewrite.cpp#L26-L72) [thread state](https://github.com/droogie/bbhost/blob/566184a74f071166299bb656c4af479e5bbe2771/tests/decomp/eboot_kit.cpp#L190-L204) [ABI](https://github.com/droogie/bbhost/blob/566184a74f071166299bb656c4af479e5bbe2771/src/guest_abi.h#L5-L13)

SUBSTITUTIONS: the kit's binding implementations resolve eight memory/string functions directly to the host; other function imports get named abort traps (stub-space exhaustion can return zero). Data imports receive zeroed 1 KiB slices, with capacity exhaustion returning zero; they are not real external library data. The selected test requires `_FSin`, `atan2f`, `tanf` bindings and redirects them to host math. The original and replacement both reach collision `0x1c090e0` and debug submission `0x135d810` redirects plus a synthetic draw-begin vtable. Quaternion-axis, quaternion-Euler and matrix-transform helpers at `0x848e80`, `0x1e4d420`, `0x83d4d0` remain calls into loaded game instructions, shared by the replacement. The offline weak hooks leave registration inert and address translation at the fixed base; the update is called directly, not via an installed replacement/trampoline. REFERENCE MODES: the loaded update's entry and masked body/constants eligibility are checked before test patches; the body check accepts known FOV/60-fps/hold bytes and rejects tested altered bytes/constants. This checks expected identity and patch recognition, not semantic equivalence. Then cameras cycle through original/patched FOV, 60-fps jump/immediate/constants, odd-camera mouse hooks and hold-NOP variants. Mouse hooks jump from the free store and two ramp exits to shared assembly, then resume at `0x183ce67`; the free stub performs displaced stores, preserves the named general registers and all XMM registers, invokes shared mouse logic, restores and resumes. Ramp stubs store pitch and mark free-camera execution. For the flag-only hold variant the original has three NOP sites, while replacement runs with original site bytes and the hold flag. These are deliberately patched references. Cameras with original update-site bytes still use loader relocations/TLS rewrites, host imports, synthetic data and collision/debug redirects; none is a wholly untouched console execution. ## Inputs, sequence and state ownership

The generator is `mt19937_64` seeded `0xca3e7a`. A camera's `0x350` bytes are filled in four-byte float words then selected fields/flags/IDs overridden; this is synthetic initial state, not a constructor-derived valid-game-state guarantee. Every fourth camera enables 15%-chance special values for `value()` calls (both zero signs, tiny denormals, extremes, infinities, quiet NaN and listed small integers). `uniform()` and integer draws do not inherit those specials. Deterministic seed does not by itself promise identical distribution sequences across standard-library implementations. [RNG and equality](https://github.com/droogie/bbhost/blob/566184a74f071166299bb656c4af479e5bbe2771/tests/decomp/eboot_kit.h#L88-L112); [special values](https://github.com/droogie/bbhost/blob/566184a74f071166299bb656c4af479e5bbe2771/tests/decomp/eboot_kit.cpp#L237-L245) [camera generator](https://github.com/droogie/bbhost/blob/566184a74f071166299bb656c4af479e5bbe2771/tests/decomp/follow_camera_test.cpp#L252-L289)

Twelve sorted parameter rows use only layout 4 with 64-bit offsets. Random IDs include valid rows, negative/unset and missing 77/zero fallback; the two other param layouts and singleton-panic setup are absent. Character pivot/positions range -50..50, rotations -3.2..3.2, sticks -1..1; alternate pad, zero sticks and yaw-only paths vary. Keep-out lists have 0..3 nodes, radius byte 0..4 and random flags; camera requests and debug/keep-out flags vary. Each frame reassigns four request bytes and a target vector in both cameras, shared overrides and the new-camera toggle. `dt` is usually 0.01..0.05, otherwise -0.1..1.0, subject to specials; world is null or one dummy pointer, followed character is null 2% of draws. Mouse counts use zero, integer -20..20, sweep -900..900 or fractional -3..3; sensitivity 0..10 and invert flags vary. These ranges identify paths, not exhaustive coverage. [params/character/list generation](https://github.com/droogie/bbhost/blob/566184a74f071166299bb656c4af479e5bbe2771/tests/decomp/follow_camera_test.cpp#L150-L249) [frame inputs](https://github.com/droogie/bbhost/blob/566184a74f071166299bb656c4af479e5bbe2771/tests/decomp/follow_camera_test.cpp#L291-L304); [counts](https://github.com/droogie/bbhost/blob/566184a74f071166299bb656c4af479e5bbe2771/tests/decomp/follow_camera_test.cpp#L346-L353); [frame loop inputs](https://github.com/droogie/bbhost/blob/566184a74f071166299bb656c4af479e5bbe2771/tests/decomp/follow_camera_test.cpp#L502-L508)

`atoi(argv[1])` has no validated positive bound; default and CTest use 2000 cameras, each 60 frames: nominal 120,000 updates per arm. A zero/negative/non-numeric small invocation is not a meaningful successful gate. The loop is serial: A original always runs first, B replacement second. Camera A and B begin as byte clones per camera and evolve separately across 60 frames unless reset after mismatch. Parameters, character/pads, keep-out/world, mapped image, helpers, flags/constants and process/TLS/FP environment are shared; their full state is not cloned or compared. [loop setup](https://github.com/droogie/bbhost/blob/566184a74f071166299bb656c4af479e5bbe2771/tests/decomp/follow_camera_test.cpp#L445-L501)

Per frame the test snapshots `0x20` GSM bytes and `0x100` shape bytes, runs A, saves its state/effect records, restores those two regions, clears records, restores free-camera predecessor flag, re-feeds counts/axes, then runs B (whose entry consumes counts again). It compares the quantities below. B's GSM/shape state persists after comparison; equal values justify that only within the selected relation. Mouse `g_frame` is regenerated; counters and globals are not comprehensively restored or compared. Flick accumulators are zeroed only after both arms. Replacement frame counters, host errno/FP status, TLS bytes, character/param/list writes and other image globals are not verified side effects. [per-arm execution/restore](https://github.com/droogie/bbhost/blob/566184a74f071166299bb656c4af479e5bbe2771/tests/decomp/follow_camera_test.cpp#L509-L558) [shared mouse state](https://github.com/droogie/bbhost/blob/566184a74f071166299bb656c4af479e5bbe2771/src/engine/mouse_camera_step.h#L67-L127)

A failed frame increments `bad` once even if several categories differ; only the first 12 failed frames get detail. If `camera_same` fails (camera OR raw GSM difference), B's camera alone is copied from A. GSM is not copied from A at that point; cast/debug/free-only differences do not resynchronize the cameras. Thus a failed run is not two uninterrupted independent trajectories. The failure count survives repairs and remains fatal at exit. Counters count updated frames, actual original-arm mouse turns, requested held frames, and configured Original-tuning frames; the latter two do not prove each held store or converted arithmetic branch was reached. The Original-tuning subset sets converted frame length to 1/30 and tuning to 30, so weights see `frames==1` and stay unchanged; it does not compare arbitrary converted-rate behavior. [failures/final exit](https://github.com/droogie/bbhost/blob/566184a74f071166299bb656c4af479e5bbe2771/tests/decomp/follow_camera_test.cpp#L558-L595) [configured tuning](https://github.com/droogie/bbhost/blob/566184a74f071166299bb656c4af479e5bbe2771/tests/decomp/follow_camera_test.cpp#L472-L479); [weight/keep](https://github.com/droogie/bbhost/blob/566184a74f071166299bb656c4af479e5bbe2771/src/engine/frame_rate_step.h#L90-L101)

## Quantity and equality matrix

All rows are post-frame observations. No comparator uses an epsilon, ULP tolerance or approximate finite-value equality. Two distinct finite encodings, signed zero, and opposite infinities differ; NaN treatment depends on the row. [word equality](https://github.com/droogie/bbhost/blob/566184a74f071166299bb656c4af479e5bbe2771/tests/decomp/follow_camera_test.cpp#L355-L365) [selected comparators](https://github.com/droogie/bbhost/blob/566184a74f071166299bb656c4af479e5bbe2771/tests/decomp/follow_camera_test.cpp#L543-L558)

| Compared quantity | Equality rule | Arms / shared dependency | Excluded behavior | Prospective falsifier |
|---|---|---|---|---|
| Camera `0x350` (212 words), including padding/flags | Each 4-byte word: identical bits OR both interpreted floats NaN (`same_float`) | A loaded update; B C++ step; shared helpers/data | NaN sign/payload, even non-float words with NaN-shaped bits; outside-object writes | Make final finite position word +0x40 differ by one bit: camera gate must fail |
| GSM first `0x20` bytes, including overrides +0x14/+0x18 | Raw `memcmp` | Shared snapshot restored between A/B | GSM beyond `0x20`, other globals | Leave one override unconsumed: raw-byte mismatch must fail even if camera equals |
| Ordered cast records: count/filter, xyz origin/delta, radius, hit/normal pointer presence | Vector/field equality; `bits()` canonicalizes every float NaN to `0x7fc00000` first | Both call same hash/salt stub | World pointer, w lanes, pointer addresses, `frac` presence, real geometry; replies not separately recorded | Omit/reorder cast or change filter/radius finite bit: record comparison must fail |
| Debug begin count, ordered submitted 12-float matrices, shape `0x100` (64 words) | Exact count/length; matrix and shape use `same()` word relation above | Common begin/submit stubs and restored shape | Begin arguments, receiver identities, rendered pixels, draw backend | Suppress one submission: count/length or matrix record must fail |
| Free-camera transition (mouse cases only) | `g_frame.free_before` boolean matches predecessor; final byte equals A | Shared mouse helper/assembly | Non-mouse transition checking, complete mouse counters/flick behavior | Flip final free byte in mouse arm: gate must fail |

The cast stub hashes frame salt and normalized question fields, produces hit if low bits permit, fraction in [0,1), interpolation hit point and a fixed upward normal. Equal questions produce equal answers under that model; recording questions detects differing camera decisions. It ignores real world geometry/materials and some arguments, so equal records cannot validate them. It can also share a wrong host-math result across arms. `normalize4()` in the replacement is arithmetic with a canonical-NaN path; it is not the equality operator and does not normalize GSM bytes. [cast/debug stubs](https://github.com/droogie/bbhost/blob/566184a74f071166299bb656c4af479e5bbe2771/tests/decomp/follow_camera_test.cpp#L75-L117) [normalize4 arithmetic](https://github.com/droogie/bbhost/blob/566184a74f071166299bb656c4af479e5bbe2771/src/decomp/camera/follow_camera.cpp#L291-L300)

| Outcome | Source branch | Meaning / required classification |

| Build unavailable / unsupported host | UNIX target, AVX/SysV and dependencies | No run; neither mismatch nor successful comparison |
| Skip 77 | Missing/unreadable input or identity mismatch | No selected frames; CMake marks 77 `SKIP_RETURN_CODE`, never comparison acceptance |
| Loader exit 1 | Mapping/stub allocation/ELF failure or wrong slide | Setup failure, no equivalence conclusion; distinguish from mismatch using diagnostic/phase |
| Test setup exit 1 | Entry/body guard rejects or required math binding absent | Eligibility/environment rejection before frame loop |

## VALIDATION CONTRACT — this selected pair

A consumer can implement this bounded contract without inventing a new framework. This is a prospective procedure, not authorization to execute it here.

1. **Freeze prerequisites.** Pin upstream commit, source blobs below, compiler/standard library and actual flags; qualify Linux x86-64 AVX/SysV, the fixed mapping, default GS TLS, FP control values and checked resource setup. Supply an authorized stable exact-hash executable in that consumer's private data area. Record load/identity/entry/body diagnostics and actual loader second-read identity; never accept skip or setup failure. Keep the synthetic singleton/params, math bindings, collision/debug stubs and original/patch-mode bytes explicit.
2. **Freeze sequence and arms.** Record seed, positive validated camera count, 60-frame boundaries and actual step count; retain exact generated inputs if cross-toolchain replay matters. Preserve clone/snapshot/restore scopes above. Name baseline-site versus FOV/60-fps/mouse/hold/flag-only reference strata rather than pooling them into an untouched-original claim. At the selected Original-tuning boundary, distinguish `frames==1` identity from untested non-unit conversion.
3. **Accept only the declared relation.** Require every applicable per-frame matrix row equal, `bad==0`, final exit 0, no skipped/fatal/guard-rejected run, and actual branch-participation evidence for any path the consumer claims. Preserve raw GSM bytes; retain raw pre-normalization words alongside normalized camera/cast/debug comparisons if payload identity matters. Exact expected finite words and effects must come from the original arm/input operation, not from the replacement/checker generating its own answer.
4. **Challenge observability before reuse.** In separately authorized testing, demonstrate the positive applicable phases and the consequential finite-output, override and cast/debug negatives below. The documented guard-byte probes are identity controls, not these semantic negatives. Stop on a negative accepted as equal, setup/trap/skip, unexplained arm-order dependence or changed source/input identity; repair the contract/environment before interpreting more counts.
5. **Minimal extra evidence for a consumer.** Produce an attributable non-skipped execution receipt for this exact pair/environment and falsifiers, including per-mode/path reachability and state-boundary control. To claim real collision behavior or original library fidelity, add independent original-world/library evidence rather than only the common stub. To adopt in a runtime project, separately authorize and measure a representative world session with zero differences plus replacement/control performance within declared noise. Specify sampling, excluded debug frames and consumer validity/coverage; do not inherit upstream author numbers as that evidence.

Four decisive prospective cases (none executed):

- **Wrong output/effect:** on a reached collision frame with finite outputs, change B's final position +0x40 by one finite bit or omit its cast. The former must fail `camera_same`, the latter `casts_same`; final `bad` must remain nonzero despite any B reset. Also leave GSM +0x14 unconsumed with equal camera: raw-byte gate must fail. A payload-only NaN mutation is an intentional blind spot for word comparison, but the same byte mutation in GSM must fail; +0/-0 and +infinity/-infinity must fail wherever finite-bit equality applies.
- **Shared-stub blind spot:** supply a different world object requiring different geometry while keeping the same normalized cast question/salt. The current stub ignores world, so both arms can agree yet be wrong about actual hit/fraction. This is not evidence that collision questions are unchecked; they are recorded. A real-world independent expected hit is the additional discriminator. Likewise original library math may differ from shared host math without this test exposing it.
- **Skip/failure discriminator:** absent/wrong-hash input must produce diagnostic plus 77 and no frames; eligible stable input with forced guard rejection must produce 1 before frames; a reached unbound import must abort; an eligible finite-output mismatch must accumulate `bad` and finish 1. A successful outer CTest command containing a skipped test must not be recorded as selected-pair acceptance.
- **State leak / boundary:** capture one finite replayable frame with nonzero counts, then a null-character/no-free-camera frame, then a zero-count release frame; replay from both fresh process state and after a previous camera, and reverse arm order while separately resetting GSM, shape, free predecessor, mouse frame/count/flick/counters and relevant image/TLS/FP status. Match per-frame camera and effects and independently compare shared inputs before/after each arm. An order-dependent result with identical explicit inputs falsifies isolation. Current A-then-B order, unreset character/params/list/TLS and counters, plus only post-pair flick reset, cannot exclude it. Distinguish intended carried free-camera predecessor from unintended leakage rather than resetting away the behavior to be tested.

## Producer, fields and observations

[Declarations and Linux branch](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_memory.c#L16-L72) define a 16 KiB API page (`PAGE=16384`), a first-fit guest placement window `[0x1000000000,0xfc00000000)`, physical `Block` entries (`uint64_t start,size`, `int type,used`) and sorted virtual `Vma` entries (`uintptr_t start,end`, `int kind,prot,type`, `uint64_t phys`). `phys` is a pool offset, not a host pointer, allocation generation or GPU-completion token. `KIND_RESERVED`, `KIND_DIRECT`, `KIND_FLEXIBLE` have different applicability. The selected public APIs use the `sysv_abi` macro ([runtime header](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime.h#L13-L27)); a source signature/static layout assertion is not an executed ABI validation.

| Producer/output | Meaning at its observation phase | Limit or contrary raw field |
|---|---|---|
| `direct_allocate` return 0 and physical `out` | A used block was entered, chunk provisioning attempted, counters updated; no virtual map yet | A physical offset of zero is valid; allocation return does not establish virtual coverage or a successful GPU allocation |
| `place`/`direct_map` return 0 and virtual `out` | Host mapping and a VMA entry were made, a non-reserved map notification queued; outer direct map flushes after unlocking | `MAP_FIXED_FLAG=0x10` can replace prior coverage; `MAP_NO_OVERWRITE=0x80` rejects non-reserved overlap. Return failure can follow host mutation |
| `VirtualQueryInfo` (72 bytes asserted) | Mapping record: start/end; direct offset or zero; stored protection/type; flexible bit 1, direct bit 2, committed bit 16 | Reserved has no committed/direct/flexible bit. A zero offset also occurs for flexible/reserved: offset alone cannot classify backing |
| `BatchEntry` (32 bytes asserted) | Raw `void* start`, U64 offset/length, int8 prot/type, int32 operation; operation selects map/unmap/protect/flexible/type-protect | `prot` is cast to uint8 before validation; `type` matters only for operation 4. `processed` counts entries before the first failed entry, not atomic batch success |
| `direct_phys(address)` true | Under a read lock, one current direct VMA yields `phys+(address-start)` and that VMA end | Flexible/reserved/gap yields false. No whole requested length, permissions, refcount, or lifetime is returned |
| `is_mapped` / `clamp` / `region` | Non-reserved coverage, prefix length or one mapped/gap region, from a generation-qualified unlocked cache or fresh locked table fallback | Coverage can cross adjacent mappings without physical contiguity; kind/coverage do not show byte stability or access rights |

Examples below constrain nonempty, nonwrapping ranges and successful surrounding setup; the C helpers do not universally validate those constraints.

## Storage, mapping and removal

[Pool and chunk backing](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_memory.c#L73-L243) creates a shared sparse memfd pool and a separate read/write backing view. Flexible offsets use storage after the direct pool. Direct mapping chooses memfd, imported-host memfd (`CHUNK_IMPORTED=-3`) or an allocator-provided dma-buf fd, with a 256 MiB chunk grid or whole-allocation regions. Provisioning failure can fall back to memfd; a physical allocation success is not proof of GPU-visible chunks. For the same physical offset under the same established backing selection, successful `MAP_SHARED` mappings alias storage even at different virtual addresses. This is a source construction, not an observed host coherence or device visibility test. Chunk sentinel, VMA kind, physical offset and virtual identity must be kept separate.

[Placement and replacement](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_memory.c#L280-L369) maps the host first, then drops old VMA records, forgets traps, inserts the new VMA, queues MAP and writes `*inout`. Fixed replacement has no explicit prior UNMAP hook in `place`. It is therefore unsafe to infer cache retirement merely from a replacement succeeding. The map hook is `[RegisterMemory then MapMemory](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/gpu/shim/bbgpu.cpp#L94-L115)`; `[rasterizer map/unmap consumers](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/gpu/shadps4/video_core/renderer_vulkan/vk_rasterizer.cpp#L4268-L4306)` maintains its own `mapped_ranges` and forwards cache work. These are separate tables/notification phases.

The region rwlock excludes table mutation during locked operations. Outermost write locking increments a U64 generation to odd, and unlock advances it to even with release ordering. Fresh `direct_phys` and fresh table-query fallbacks use the runtime read-lock helper; `is_mapped`, `clamp` and `region` can instead return from their per-thread cache **before acquiring that lock**. A fast positive requires an observed even generation matching the cached entry and the applicable kind/address/length predicate. An odd generation or a cache-generation mismatch defeats that runtime cache path and leads to its locked fallback; cache disabling does likewise ([runtime cache and fallbacks](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_memory.c#L961-L1034)). The shim's separate `CachedMapped` also returns true without locking for its even matching cached range. Its odd-generation branch returns false; a mismatched even generation calls `runtime_memory_region`, which may itself use the runtime cache rather than a fresh locked lookup ([shim cache](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/gpu/shim/bbgpu.cpp#L130-L155)). These observations retain no reference or exclusion against a writer beginning after the generation sample or after a lookup unlocks. The generation is a cache-validity device, not an allocation identity, lease or stable content version, and the runtime lock does not serialize ordinary guest stores against a host copy ([locking](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_memory.c#L56-L72), [direct translator](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_memory.c#L885-L894), [cached shim copy consumer](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/gpu/shim/bbgpu.cpp#L120-L198)). In precise readback mode, `CopySparseSerial` uses `read_backing`; otherwise it queries and later memcpy-reads the virtual address. The former holds the runtime read lock during its copy; the latter can copy after an unlocked cache return or a fresh coverage lookup has ended. Neither establishes a stable content version against unrelated writers.

[Unmap and release](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_memory.c#L440-L498) differ in ordering. Standalone `direct_unmap` invokes the unmap hook for the aligned requested range **before** taking the runtime write lock; queued per-VMA notifications are then suppressed, including on failure. Batch unmap queues clipped non-reserved spans and flushes after the batch unlock. Physical release calls `unmap_locked` for overlapping direct aliases under the lock but ignores its return and resets its index to `vma_index(v.start)`. If the unmap succeeds, the changed records allow the alias loop to advance; only after that loop finishes does release edit/split blocks, attempt zeroing, unlock, flush queued hooks and return 0. A failed munmap returns before VMA removal. With the same still-overlapping VMA and persistent failure, release selects that unchanged record again: a stable installed UNMAP hook queues repeated entries until the 64-entry queue exits(21), while no hook permits indefinite repetition ([failure before record removal](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_memory.c#L440-L454), [release retry and later phases](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_memory.c#L466-L498), [hook queue limit](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_memory.c#L244-L248)). Neither persistent-failure branch reaches block edits, zeroing, unlock, flush or return 0; a later successful retry is a different schedule. After successful alias removal, GPU chunks are cleared through backing storage and memfd storage is hole-punched. A hole-punch return is ignored and can still be followed by normal return 0 ([zero_phys](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_memory.c#L221-L243)). This is attempted zero-on-reuse, not a verified secure-clear or transactional result. The failure branches are static source conclusions, not executed fault injection, observed frequency or proof of target reachability.

The unmap consumer queues in-place removal for later maintenance ([UnmapInPlace](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/gpu/shadps4/video_core/buffer_cache/buffer_cache.cpp#L2967-L2986)), calls a context-dependent draw-pipe drain ([DrainDrawPipe](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/gpu/shadps4/video_core/renderer_vulkan/vk_rasterizer.cpp#L835-L849)), invalidates cache memory, frees overlapping texture entries ([Texture unmap](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/gpu/shadps4/video_core/texture_cache/texture_cache.cpp#L271-L280)) and removes rasterizer coverage. It supplies no general completion token for every in-flight CPU/device reader. This trace stops at these decisive public endpoints; downstream whole-renderer scheduling, fences, cache lifetime and allocator-owner reuse are unqualified.

## Protection and failure ordering

Stored `prot` permits only bits in `0x37`. [host_prot](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_memory.c#L130-L135) translates 0x11 to host read, 0x22 to host write plus read, and bit 4 to host execute plus read. Thus stored guest protection, host permission and GPU bits are not interchangeable. Reserve creates PROT_NONE host coverage and a reserved VMA without a map notification ([reserve/protect](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_memory.c#L542-L573)).

`protect_locked` rounds its start down and its end from the original start plus rounded size; requires non-reserved coverage; host mprotect occurs first, **then trap reapplication using the old stored VMA prot**, then carving/field update and INVALIDATE queueing. A trap read-only level masks host write; high-nibble reason bits mask all access. Successful protection change does not imply the requested new host access on trapped pages, because `trap_apply` consults old VMA fields at that phase ([trap application and reapply](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_memory.c#L794-L865)). Reasons are U8 per 4 KiB page below `2^40`; owners OR/clear their own reason under runtime read lock then trap mutex. Removing Image=2 cannot clear Mirror=1; VramData=32 yields no-access until its reason is removed ([named reasons](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/gpu/layer/bblayer_write_traps.h#L1-L35)). Replacing/unmapping coverage forgets reasons. The inspected trap mprotect return values are ignored; bit state is not proof that host protection was successfully installed.

Failure is not a rollback promise. A multi-chunk `map_phys` can map earlier chunks before a later MAP_FAILED. `place` can modify host/VMA/traps before VMA insertion fails. `split_at` changes the left endpoint before insertion, and `drop_range` does not act on carve's error. Protection can modify host permissions before carving returns NO_MEMORY. Unmap queues before munmap and can fail after earlier pieces disappear. Batch stops at first failure while earlier effects remain. These conditional branches are source limits, not an observed failure rate or proof that an actual target reaches them ([map helper](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_memory.c#L181-L220), [table helper and place](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_memory.c#L280-L369), [unmap](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_memory.c#L440-L465), [protect](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_memory.c#L554-L573), [batch](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_memory.c#L618-L641)).

Queued hooks have U64 size and virtual address, but no physical identity, generation or completion output. The 64-entry global queue exits(21) on overflow. `flush_hooks` removes one entry under the lock and invokes it after unlocking: single-threaded calls dispatch queue entries FIFO, but concurrent flushers can remove H1/H2 and invoke H2 first. A hook also resolves the then-current hook pointer. The comment saying notifications run “in order” does not establish cross-thread invocation ordering or an immutable mapping snapshot ([hook queue and flush](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_memory.c#L120-L128), [queue/flush bodies](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_memory.c#L244-L261), [installation replay](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_memory.c#L725-L754)). Treat serialized calling/setup as a premise, not an observed invariant.

## A bounded host write has two notification routes

The installed hooks lead to different consumers ([SetRasterizer](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/gpu/shim/bbgpu.cpp#L94-L115)): map/register, unmap, generic invalidate, asset note, and OnCpuWrite. Installing GPU hooks replays all current non-reserved VMAs; CPU hook setup allocates a bitmap, but can return without installing on mmap failure. Setup concurrency/lifetime is not qualified by these unsynchronized setter fields.

| Route | Producer predicate and phase | Consumer and limit |
|---|---|---|
| `runtime_memory_note_write` | Requires `hook_invalidate` and nonzero size even if asset hook exists; under read lock collects up to **8** non-reserved VMA intersections with `prot & 0x30`; unlocks, calls asset hook or invalidate for clipped spans | File read/pread calls it before touch/read with requested size and after a positive read with actual n. It can announce before any bytes change, after partial reads, or without a successful read. More than 8 eligible spans are not all announced |
| `prepare_cpu_write` | Before libc store: acquired trap-table pointer, nonzero range beginning below `2^40`, installed CPU hook, any nonzero trap byte on intersected page | Calls OnCpuWrite once for the **original full range**, without checking mapped coverage or watch bits; clamps scan end but not callback size |
| `note_cpu_write` | After libc return: bitmap exists, nonzero range wholly below/equal to `2^40` end, any watched-page bit (acquire) | Calls CPU hook once for original full range; no VMA clipping/prot/physical alias scan. Unlike prepare, body has no explicit null-hook guard |

[note/write bitmap/CPU notes](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_memory.c#L735-L793), [prepare](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_memory.c#L866-L880), [libc wrappers](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime.c#L179-L193), [file write-into-buffer path](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_file.c#L394-L436) bind those predicates and order. For note_cpu_write use successfully installed stable nonnull hook as a premise. Neither preparation nor a returned callback means the subsequent libc write succeeded; a fault/termination can prevent the after-call note. Atomic bitmap release/acquire publishes watched bits, not the payload as one content version. Arithmetic overflow is not uniformly rejected by these helpers, and their page-keyed arrays track virtual addresses, not all aliases of one physical offset. This study's positive cases use nonwrapping bounded addresses; cross-alias notification completeness is not established.

The decisive consumer [OnCpuWrite / invalidation](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/gpu/shadps4/video_core/renderer_vulkan/vk_rasterizer.cpp#L4191-L4242) increments counters before checking whole-range rasterizer IsMapped. IsMapped rejects zero/wrap and requires containment in **rasterizer** mapped_ranges. Eligible OnCpuWrite calls InvalidateAfterWrite and NoteCpuWriteRange; WriteTracking or no GPU modification takes normal invalidation, otherwise precise-upload notification plus texture invalidation. A counter increment is therefore not even proof of accepted rasterizer coverage. [cache asset and CPU note endpoints](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/gpu/shadps4/video_core/buffer_cache/buffer_cache.cpp#L2228-L2262) are bookkeeping, not reader-completion receipts. [texture invalidation](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/gpu/shadps4/video_core/texture_cache/texture_cache.cpp#L194-L226) marks overlapping images CpuDirty and untracks them; [UntrackImage](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/gpu/shadps4/video_core/texture_cache/texture_cache.cpp#L1124-L1136) feeds page watchers. This trace establishes that notification paths exist, not device coherence or general renderer correctness.

[write-tracking mode computation](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/gpu/shadps4/video_core/buffer_cache/buffer_cache.cpp#L482-L527) uses latched first-character `1` settings: GuestInPlace can be disabled; WriteTracking is forced or !GuestInPlace; WriteVerify requires tracking off. SignalImpl in tracking-off mode sets virtual watch bits and may skip page protection; image traps separately require GuestInPlace, !WriteTracking, !WriteVerify and BB_IMAGE_TRAPS not beginning `0`. Image counts add/clear only their Image reason, and the fault handler examines reasons before selecting cache callbacks ([image-trap configuration](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/gpu/shadps4/video_core/page_manager.cpp#L226-L244), [fault handler](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/gpu/shadps4/video_core/page_manager.cpp#L309-L346), [image trap producer](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/gpu/shadps4/video_core/page_manager.cpp#L486-L530), [signal mode selection/watch protection](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/gpu/shadps4/video_core/page_manager.cpp#L690-L758)). Userfaultfd selection and dma-buf exclusion differ; these are source branches, not exercised configuration or hardware evidence. No flag by itself is a write-coverage receipt.

## Conditional worked positives and contrary cases

All rows are original source reasoning, **not executed tests or model-generated expectations of original hardware**. Unless a row varies it, assume Linux, stable successful pool/hook setup, nonempty nonwrapping bounded addresses, serialized calls, successful host calls and metadata allocation, and reached stated phase. Let `A=0x1000000000`, `B=A+0x10000`, page size `P=0x4000`. Source citations above define each branch independently of the row's labels.

| Case / inputs and observation | Supported outcome | Contrary input/phase and falsifier |
|---|---|---|
| 1. Allocate physical `[0,2P)`, type 0, alignment P within pool; return 0 | Block owns that pool interval; physical out may be 0 | Before map, is_mapped(A,P) need not be true; offset zero alone fails a mapped/backing claim |
| 2. | 3. Map allocated `[0,2P)` at fixed A and B, same backing choice | At A+0x1000 and B+0x1000 direct_phys gives 0x1000, separate VMA ends; shared physical storage | Change B's physical offset to another allocated span: virtual coverage remains but alias equality no longer follows |
| 4. Split direct A map by successful protection of second P | Right direct VMA phys advances P; bounded direct query can recover offset | Adjacent new map has noncontiguous phys: is_mapped/clamp may cover both but layer ResolveInPlace fails full physical continuity; each query's lock is already released |
| 5. Direct `[A,A+P)`, old prot 0x33, trap reasons Mirror|Image=3; clear Image | Mirror remains, read-only level; clear Mirror too restores host_prot(stored prot) if mprotect succeeds | VramData=32 remaining yields no-access. | 6. | 8. | 11. Two aliases A/B to phys=0; only A page watched, write via B | Data aliasing can hold while B's note_cpu_write sees no watched bit | A's bit does not notify B; a source-backed alias-coherence result is not all-alias notification coverage |
| 12. note_write spans 9 eligible separated direct VMAs, each prot 0x30, asset hook and invalidate installed | First 8 eligible intersections copied and dispatched | Ninth not collected. prot 0x3 instead excludes an otherwise mapped VMA; invalidate=null suppresses all even with asset hook |
| 13. File do_read valid fd, requested 64, actual n=7 | Pre-note/touch for requested bytes; post-note only 7 after successful return | n=0 or error has no positive post-note; pre-note is not evidence 64 bytes were written |
| 14. CPU range starts below 2^40, crosses limit, trap in scanned prefix | prepare may call with original crossing range; post note_cpu_write refuses it | OnCpuWrite can count and then reject missing whole rasterizer coverage; notification count is not coverage/visibility |
| 15. H1 then H2 dequeued by concurrent flushers | FIFO removal only; H1 can pause before callback while H2 invokes | Inferring globally ordered callback completion from queue order fails; positive requires serialized dispatch premise |
| 16. Runtime cache enabled, acquired generation=2, cached generation=2, direct region `[A,A+P)` and request `(A,16)` | is_mapped returns 1 / clamp returns 16 from cache before read_lock; region returns cached fields. Even matching shim cache with the same bounded range also returns true without locking | Acquired generation=3 or generation=4 with only cached generation=2 defeats the runtime fast path and reaches read_lock; reserved kind defeats is_mapped/clamp positive (region may return mapped=0).

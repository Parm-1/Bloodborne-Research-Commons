Write success reports transferred bytes and can be short; it does not by itself guarantee storage commitment. Pwrite ordinarily uses its supplied offset without moving file position, but the Linux description explicitly warns that O_APPEND appends despite that offset. File fsync success and directory-entry persistence are distinct: the description requires directory fsync for the latter. On NFS a failed rename may already have happened, so a source error/log cannot universally certify that old bytes remain. Fwrite counts items (bytes here because item size1); fflush drains userspace buffering, while fclose flushes/closes and can fail. Both differ from kernel/directory persistence. ## Copy selection, transfer and captured close

[src/runtime_file.c:232–284](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_file.c#L232-L284) chooses current_copy by scanning used file slots3..1023 for the **first lowest-index exact commit path**, then copies its temp text. Read-open/stat/access can see that unfinished copy; a second writer seeds from it unless truncating. Selection is not a lock held across host operations. For a low-mode write request on a save-prefixed guest, open_for_commit stats the selected source; existing nonregular sources take ordinary open of the original path without commit/temp. A failed stat is treated as absent. Existing CREATE|EXCL is rejected; absent without CREATE is rejected. Otherwise it allocates destination text and a temp name destination.serial.bbtmp, opens that temp for writing/create/truncate, copies existing bytes unless O_TRUNC, closes the seed output **unchecked**, then reopens with translated guest flags minus CREATE/EXCL/TRUNC. The initial temp open lacks O_EXCL and temp_serial is finite/process-local; unique safe temp identity is a premise, not a guaranteed cross-process lease. Permissions bits are copied from stat, subject to host creation rules; ownership/full metadata preservation is unqualified.

Copy read and negative write EINTR retry; positive short copy writes loop. A zero copy write makes no progress and has no explicit termination rule. Failure cleanup unlinks temp and frees names, with ignored cleanup outcomes. Copy error errno is read after possible intervening operations (including a successful source open); it is not a universal original-error identity. do_open's optional trace also precedes errno capture. Reuse the file-read error-preservation qualification: no blanket exact-errno claim. Successful open allocates a reusable guest slot and captures host descriptor, commit and temp; dirty defaults0. No actual file lease/generation/reference is acquired by get/host_fd. Eligible statements here require caller ordering without conflicting close/reuse/field access, stable mappings/pointers/paths and normally returning host/hook calls.

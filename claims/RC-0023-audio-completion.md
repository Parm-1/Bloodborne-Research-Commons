Output's uint64 monotonic deadline is scheduling state: startup/stall resets without waiting, later non-null paced calls wait at the saved deadline before submission. NULL output skips the wait but still writes last_output_us. That uint64 microsecond value, non-null buffers_out counter and type-derived32-byte PortState describe host operations, not played sample positions. SDL queued input bytes are sampled before submission; after attempted underrun prefill the source overwrites its local queued value with2×buffer bytes without measuring again or checking Put. Thus queue-control minima can include synthetic values; -1 is API failure, not valid occupancy. No selected return/state/time field establishes actual playback completion. Close destroys the stream; official SDL Destroy releases remaining queued audio rather than documenting a drain-to-playback endpoint.

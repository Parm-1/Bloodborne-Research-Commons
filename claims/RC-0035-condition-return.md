# RC-0035 — Condition return does not establish the caller predicate

**Level:** proposed SOURCE_INSPECTED, checked2026-10-16. BRC-MUTEX-COND-01 / Batch04 [Issue #24](https://github.com/Parm-1/Bloodborne-Research-Commons/issues/24). Subject: public bbport `3c57da4198ad62039f63f33bfd205b9916518acf`, selected non-Windows branch. Reviewer: pending; parent conditional acceptance and owner editorial acceptance/merge pending. No supersession.

The selected condition wrapper delegates once to host wait/timedwait and maintains no caller predicate. For valid ordinary depth1 waits under the stated host contract, success or timeout follows mutex release/reacquisition, but neither result determines predicate truth. Signal/broadcast return is a separate endpoint from a matching wait's return. Caller ownership and applicable condition/mutex binding must already hold; the wrapper checks a numeric mutex range, not ownership.

**Primary:** [src/runtime_mutex.c:132–222](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_mutex.c#L132-L222), blob `7542d2b038cb1431e732ee8b435a8be8b5554a30`; separate [POSIX wait](https://man7.org/linux/man-pages/man3/pthread_cond_wait.3p.html) and [mutex-type caution](https://man7.org/linux/man-pages/man3/pthread_mutexattr_gettype.3p.html). [Dossier](../knowledge/mutex-condition.md) binds producer/intake/deadline/lifetime premises and cases C1–C6/D1–D3.

**Meaningful negatives:** a normal wait0 can accompany predicatefalse; timeout raw32 `0x8002003c`/POSIX60 can accompany predicatetrue. Invalid absolute nsec returns EINVAL before waiting. Mutex raw0 is rejected after possible condition lazy creation; raw2 condition is accepted by admission but is invalid storage, not a defined EINVAL outcome. Recursive depth2 does not establish full release. Successful condition destroy writesNULL, so a later signal can lazily create a different condition with no waiter; signal0/wakeups1 does not retire the old caller. Copied aliases are not revoked.

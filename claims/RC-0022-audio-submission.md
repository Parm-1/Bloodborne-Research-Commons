For a valid normally returning non-null output call on a serial stable open slot, with correct native interface and readable stable input extent, bbport synchronously reads/converts frames×channels samples before pacing and SDL submission. It retains no source input pointer and returns that computed int32 sample count. A timer sink returns the same count. On a stream it ignores both silence and converted SDL Put success/failure, so the return alone does not establish acceptance. Under separately supplied compatible API and same-call Put=true premises, official SDL3 Put semantics copy converted input for later conversion. Source slot lookup does not retain an incarnation across concurrent close/reopen; that schedule is outside the valid positive's setup.

# RC-0028 — Successful matching host join closes one host thread, not guest resource lifetime

**Level:** SOURCE_INSPECTED, checked2026-10-14; public bbport `3c57da4198ad62039f63f33bfd205b9916518acf`, selected Linux/x86-64 implementation. Proposed BRC-THREAD-LIFECYCLE-01 / Batch03 [Issue #20](https://github.com/Parm-1/Bloodborne-Research-Commons/issues/20) goal2. Independent review and human editorial acceptance/merge pending. Original prose/references, KNOWLEDGE_REFERENCE; GPL v2-or-later declaration and [registry caveats](../sources/projects.yaml) apply to upstream adaptation. No earlier claim superseded.

For ordered eligible access to a known guest-created record, wrapper join0 follows successful pthread_join on its recorded host thread. Under the separate host API contract that thread has terminated. The wrapper writes joined1 before that wait; host_start writes finished1 before returning. Neither field alone is a termination endpoint. Record, separately allocated static TLS and caller-mapped stack are not freed by join/detach in this implementation. Host-owned attachment is rejected by guest join; guest detach0 ignores the host detach outcome and does not wait. This is not transitive guest-job completion or resource-retirement proof.

**Primary:** [runtime_thread.c:220–285](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_thread.c#L220-L285), blob `12acdc26c13ca8411b439f4e67eebb37fb8651b0`; [primary pthread_join description](https://man7.org/linux/man-pages/man3/pthread_join.3.html). **Meaningful contrary:** joined1 before host wait completes; finished1 before host_start return; serial repeat join22; host_owned join3; host detach error coexists with guest0; retained record survives join. Host value returned by pthread_join is ignored in favor of t->result, so result/cleanup claims additionally require ordinary entry-return/valid explicit-exit and normally returning stable key cleanup. Cancellation/bypassed tail cannot be assigned that result guarantee.

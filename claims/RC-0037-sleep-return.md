# RC-0037 — Valid-input sleep return masks the final host sleep result

**Level:** proposed SOURCE_INSPECTED, checked2026-10-16. BRC-CLOCK-SLEEP-01 / Batch04 [Issue #24](https://github.com/Parm-1/Bloodborne-Research-Commons/issues/24). Subject: public bbport `3c57da4198ad62039f63f33bfd205b9916518acf`, selected non-Windows wrappers. Independent reviewer, parent conditional acceptance and owner editorial acceptance/merge pending; no supersession.

The shared helper retries host EINTR with its local remainder, stops on host success or non-EINTR error, and returns a result that all selected sleep wrappers ignore. On the valid-input normal-return path, POSIX/SCE nanosleep return0 and clear supplied rem even after a non-EINTR host error. Thus wrapper0/rem0 alone cannot distinguish completed host relative sleep from a discarded error, establish the original unwrapped request duration, or prove a caller deadline/predicate.

**Primary:** [src/runtime_kernel.c:112–138](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_kernel.c#L112-L138), blob `19909ea6f8f5d17b3f20028a324b70b4c5bcec7f`. Separate [Linux nanosleep description](https://man7.org/linux/man-pages/man2/nanosleep.2.html) supplies a conditional host success/EINTR contract, not installed-host proof. [Dossier](../knowledge/clock-sleep.md) binds actual resolver applicability, adapter/TLS/error phases, native conversion and diagnostic bounds, and source/model cases S1–S4/D1. No wrapper/host execution occurred.

**Meaningful negatives:** rq(0,1000000000) fails validation with POSIX-1/TLS22 or SCE raw32 `0x80020016`, leaves rem unchanged and makes no helper call. Valid rq plus host error can instead produce0/rem0 with stale guest TLS35. Positive sec18446744074 passes validation but uint64 scaling wraps to290448384ns before host conversion. Count increments once per helper that reaches instrumentation, not once per EINTR attempt, and counts host failure too. Measured a→b ns differs from requested ns; separate atomic exchanges can split count/duration across snapshots.

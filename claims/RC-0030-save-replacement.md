# RC-0030 — Dirty regular-copy close0 checks file fsync and rename, conditional replacement

**Level:** proposed SOURCE_INSPECTED, checked2026-10-14; BRC-SAVE-COMMIT-01 / Batch03 [Issue #20](https://github.com/Parm-1/Bloodborne-Research-Commons/issues/20) goal3. For an ordered normally returning close of a captured dirty regular save-copy File, close0 means commit_file observed fsync(host)0 and rename(temp,commit)0. Under stable unique nonaliased temp/destination identity and the separate applicable host API semantics, the copy replaces the named destination at rename. Complete intended bytes additionally require checked full transfers and exact copy/truncate/offset/length premises. This is a conditional source/API contract, not runtime or durability evidence.

**Primary:** [src/runtime_file.c:232–379](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_file.c#L232-L379), blob `461f9907fc246dc80b3c86deb24071307b0e1c6a`; [src/runtime_file.c:438–462](https://github.com/deadinside28/bloodborne_pc/blob/3c57da4198ad62039f63f33bfd205b9916518acf/src/runtime_file.c#L438-L462); [primary rename description](https://man7.org/linux/man-pages/man2/rename.2.html), [write description](https://man7.org/linux/man-pages/man2/write.2.html). [Dossier](../knowledge/save-commit.md) binds eleven source blobs/bounds, seven separately inspected mutable API descriptions and twenty conditional cases. File-read open/close/error receipts reused unchanged.

**Meaningful negative:** dirty1 is set before host mutation. Request3/return1 or zero/error followed by fsync0/rename0 can still close0 without completed intended bytes. Dirty0 close0 discards temp; lowmode0/TRUNC may use ordinary open. Earlier descriptor to old inode remains unaffected; multiple writers can overwrite each other. File-fsync failure skips rename and returns its captured error; failed rename does not universally prove old bytes remain, especially NFS.
